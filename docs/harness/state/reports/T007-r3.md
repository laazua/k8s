## 4. 缺陷清单

### [MINOR] M6 · 冷缓存无法自举，且 README/契约声称「进入 netns 之前填充」与实现相反

- 位置：
  - `tests/control-plane/test_control_plane_roles.sh:94-106`（无条件 `exec sudo -n ... unshare -n`）
  - `tests/control-plane/test_control_plane_roles.sh:324-340`（`ensure_artifact`/`ensure_etcd_tarball` 用 `curl` 填缓存，**在 re-exec 之后**）
  - `tests/control-plane/README.md:27`、`docs/harness/state/contracts/T007.md:478`（「缓存缺失时会在**进入 netns 之前**一次性填充」）
- 复现：
  ```bash
  # 宿主网络正常，但缓存目录为空：
  T007_TEST_CACHE=/tmp/opencode/eval-t007r3/emptycache \
    ./tests/control-plane/test_control_plane_roles.sh
  # → rc=1；curl: (6) Could not resolve host: dl.k8s.io
  #   FAIL 无法获取/校验官方制品 kube-apiserver
  #   == 汇总: PASS=137 FAIL=1 ==            # /tmp/opencode/eval-t007r3/coldcache.log
  ```
- 期望：按 README/契约，首次运行（缓存缺失）应在进入 netns **之前**把缓存填好；或明确声明「缓存是外部前置」并给出 seed 命令。
- 实际：re-exec 在缓存填充之前执行，冷缓存时 `curl` 在 netns 内必然 DNS 失败；**新主机即使有网也无法一次跑通 `make test`**，且文档描述与实现相反。
- 影响：**非阻塞**。本机缓存就位时两次门禁与断网复跑全绿；缓存缺失时是**明确失败**（满足「移走缓存 + 断网 → 必须明确失败」的反证要求），不会静默联网。
- 建议方向（二选一，改测试/文档，不改产品）：
  1. 把 `ensure_artifact`/`ensure_etcd_tarball` 移到 re-exec 之前（或在 re-exec 前检测 `$CACHE` 缺失 → 先填充再隔离）；或
  2. 保留现状但修正 `README.md:27` 与契约 `§10.9:478`：写明「首次需在**未隔离**环境预热缓存（给出命令），此后完全离线」，并在缓存缺失时输出该提示。

### [NIT] N5 · re-exec 的 `PYTHONPATH` 在空值时产生前导冒号（CWD 进入 `sys.path`，且以 root 运行）

- 位置：`tests/control-plane/test_control_plane_roles.sh:99`
- 复现：`PYTHONPATH= sudo -n env PYTHONPATH=":/home/x/.local/lib/python3.11/site-packages" python3 -c 'import sys;print(repr(sys.path[0]))'` → `''`（当前目录）。
- 期望：只在 `PYTHONPATH` 非空时拼接冒号。
- 实际：`"${PYTHONPATH:-}${USER_SITE:+:${USER_SITE}}"` 在空值时得到 `:<usersite>`。
- 影响：低（套件在可信仓库根目录以 root 运行）；建议改为 `${PYTHONPATH:+$PYTHONPATH:}${USER_SITE:-}`。

### [NIT] N6 · `stack_uses_cache` 静态判定依赖 playbook 文本缩进（脆弱）

- 位置：`tests/control-plane/test_control_plane_roles.sh:386-395`

  `sandbox_stack.yml` 结构调整（缩进/键名），可能误判。**动态 B0（不可达 URL 实跑 + sha256 比对）**
