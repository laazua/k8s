## 4. 缺陷清单

### [BLOCKER] D1：A8 负例恒真假绿（未真实触发 become 失败且吞掉退出码）
- 位置：`tests/t020/test_t020.sh:196-216`
- 复现：单独执行 A8 中的 `play.yml`（见 §1 第 2 段），观察到 `ok=2 failed=0 RC=0`。
- 期望：模拟「缺少免密 sudo」场景时，`ansible-playbook` 必须返回**非 0 退出码**，且失败错误信息（非 PLAY/TASK 标题）中真实包含 sudo/become 密码缺失提示。
- 实际：由于测试机 `zhangsan` 拥有 `NOPASSWD` sudo，传入错误的 `ansible_become_pass` 并不会失败；测试脚本又使用 `|| true` 忽略退出码，并用 `grep -qiE "sudo|become|..."` 匹配了自身的 `PLAY [T020 负例：become 失败]` 标题行，导致恒真假绿。
- 建议方向：
  1. 在 `SB_NEG` 中构造一个 mock `sudo` 脚本（例如置于 `$SB_NEG/bin/sudo`，打印 `sudo: a password is required` 到 stderr 并 `exit 1`），通过 `PATH="$SB_NEG/bin:$PATH"` 或 `-e ansible_become_exe="$SB_NEG/bin/sudo"` 真实模拟无 `NOPASSWD` 的节点环境；
  2. 去掉无条件 `|| true`，明确断言 `ansible-playbook` 返回**非 0 退出码**；
  3. Play/Task 标题中避免使用待匹配关键词（或仅在 `fatal:`/`FAILED!` 错误行中检索提示）。

### [MAJOR] D2：A6 未校验沙箱落盘文件属主为 `root`
- 位置：`tests/t020/test_t020.sh:153-162`
- 复现：若将 `tests/t020/test_t020.sh:135` 的 `become: true` 删去，A6 仍会因创建沙箱目录/文件而返回 `rc=0` 且 `changed>=1`。
- 期望：按 `roadmap.md` T020 验收标准（`首次 changed>0 且落盘属主 root`），A6 必须校验 `roles/base` 在 `$SB` 下落盘的文件（如 `$SB/etc/hosts` 或 `$SB/etc/sysctl.d/99-kubernetes.conf`）属主为 `root`（`stat -c '%U'`）。
- 实际：只断言了 `rc=0` 与 `changed >= 1`，未做属主断言。
- 建议方向：在 A6 首跑通过后，增加 `[[ "$(stat -c '%U' "$SB/etc/hosts")" == "root" ]]`（或对 `$SB/etc/sysctl.d/99-kubernetes.conf`）的断言，并用「临时去掉 `become: true` 必红」验证牙齿。

### [MINOR] D3：A1 对 `site.yml` 仅检查文件存在，未显式校验子 play 接线
- 位置：`tests/t020/test_t020.sh:47`
