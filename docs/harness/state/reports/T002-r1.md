## 6. 缺陷清单

### [MAJOR] D1 · Debian/Ubuntu 分支的 NTP 服务名默认值错误（本轮 FAIL 原因）
- 位置：`roles/base/defaults/main.yml:46`（`base_ntp_service: chronyd`）、`roles/base/tasks/system.yml:50-58`（未按 `ansible_os_family` 分支）；宣称支持的平台见 `roles/base/README.md:3`、`roles/base/meta/main.yml:11-14`
- 复现：
  ```bash
  # Debian 12 的 chrony 包文件列表（实测）
  curl -s https://packages.debian.org/bookworm/amd64/chrony/filelist \
    | grep -oE '/lib/systemd/system/[a-zA-Z0-9_.-]+\.service'
  # 输出：/lib/systemd/system/chrony.service
  #        /lib/systemd/system/chrony-wait.service
  # 本机（Rocky）则为 chronyd.service；用错误服务名做 check 探针：
  ansible-playbook ... -e base_ntp_service=chronyd-not-a-real-service \
    --check --tags base:system:ntp --start-at-task '启用并启动时间同步服务'
  # exit 2, "Could not find the requested service ..."
  ```
- 期望：在 Debian/Ubuntu 上 `base_ntp_enabled: true`（默认）时 role 成功安装并启动 chrony。
- 实际：默认服务名 `chronyd` 在 Debian/Ubuntu 不存在，`ansible.builtin.service` 任务 fatal，整个 play 失败。README/meta 宣称的 Debian/Ubuntu 支持不成立。
- 建议方向：
  1. 把默认值改为按发行版求值，例如
     `base_ntp_service: "{{ 'chronyd' if ansible_os_family == 'RedHat' else 'chrony' }}"`；
     或在 `system.yml` 中按 `ansible_os_family` 分支，保留用户覆盖能力。
  2. README「关键变量」补上 `base_ntp_service`（以及 Debian 覆盖说明，若不做自动分支）。
  3. 增加一个跨发行版断言（至少验证 `ansible_os_family=Debian` 时解析为 `chrony`），避免再次假绿。

### [MINOR] D2 · A5 测试未断言 hosts 自定义条目内容
- 位置：`tests/base/test_base_role.sh:74-76`；被测实现 `roles/base/tasks/files.yml:37-48`
- 复现：临时副本删除 `files.yml` 中 `{% for h in base_hosts_entries %}` 循环，`tests/base/test_base_role.sh` → `PASS=31 FAIL=0`。
- 期望：契约 A5 要求「含受管块与自定义条目」，测试应断言 `10.0.0.11 k8s-master1`、`10.0.0.21 k8s-node1`。
- 实际：只断言 `BEGIN ANSIBLE MANAGED BLOCK` 与原 hosts 行；空受管块也能通过。
- 建议方向：增加两条 `grep -qx '10.0.0.11 k8s-master1'` / `grep -qx '10.0.0.21 k8s-node1'`；可再加一条“修改 entries 后块内容更新”的断言。

### [MINOR] D3 · A10 隔离断言只覆盖 `/etc/sysctl.d/99-kubernetes.conf`
- 位置：`tests/base/test_base_role.sh:115-121`
- 复现：读代码 + E5；A10 只比较 sysctl 文件的前后状态。
- 期望：契约 A10 的「不污染宿主」应覆盖 role 会写的全部真实路径：`/etc/sysctl.d/99-kubernetes.conf`、`/etc/modules-load.d/99-kubernetes.conf`、`/etc/hosts`、`/etc/fstab`。
- 实际：只查 sysctl；若未来某个路径绕过前缀，A10 可能仍通过（虽然 A2/A4/A5 的沙箱内容断言通常会间接暴露）。E5 已证明当前 sysctl 断言本身有效。
- 建议方向：把四个宿主路径的前后哈希/内容一起比较；或统一 `base_root_prefix` 派生断言（确保所有 dest 都以 `base_root_prefix` 开头）。

### [MINOR] D4 · 文档中的环境事实「无 systemd」与实测不符
- 位置：`docs/harness/state/contracts/T002.md:38`、`roles/base/README.md:49-51`（以及 spec R1，Planner 所有）
- 复现：
  ```bash
  ps -p 1 -o pid,comm,args --no-headers
  # 1 systemd /usr/lib/systemd/systemd --switched-root ...
  systemctl is-system-running
  # degraded
  ```
- 期望：文档描述实际环境；若确实无 root 无法做主机级变更，应把限制归因于「无 root/无特权」，而不是「无 systemd」。
- 实际：PID1 是 systemd；受限结论（不能真实改主机）仍因无 root 成立，但文档事实不准确，可能误导后续任务对 systemd 相关验收的判断。
- 建议方向：Planner 修订 spec R1 / 契约 §5 / role README 的措辞为「systemd 存在但无 root/无特权，无法执行主机级变更」；若环境已变化，重新评估可验证范围。**非代码阻塞项。**
