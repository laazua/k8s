## 4. 缺陷清单（按严重度排序）

### [BLOCKER] `ansible.cfg` 的 `stdout_callback = yaml` 使任何真实 playbook 运行 exit 1
- 位置：`ansible.cfg:12`
- 复现：
  ```bash
  cd /opt/codes/k8s && export PYTHONPATH=/home/zhangsan/ansible
  /home/zhangsan/ansible/bin/ansible-playbook -i inventory/hosts.example playbooks/site.yml
  ```
- 期望：exit 0，输出 `PLAY RECAP`（骨架可运行）。
- 实际：
  ```
  [ERROR]: The 'community.general.yaml' callback plugin has been removed. ... from ansible-core 2.13 onwards. ...
  real-run EXIT=1
  ```
  （`ansible-doc -t callback -l` 中**无 `yaml` callback**；`community.general 12.6.0` 已于 12.0.0 移除该插件。）
- 影响：任何真实运行立即失败 → **T002+ 全部受阻**；同时 `make lint`/`make test`（仅 `--syntax-check` + yamllint）对它**假绿**。
- 建议方向：二选一（均已本地验证可行）
  1. 删除 `ansible.cfg:12` 整行；或
  2. 改为 ansible-core 2.13+ 的正规写法：`callback_result_format = yaml`（在 `[defaults]` 段）。
  > 我已在 `/tmp` 副本验证：删行 → `probe_play.yml` exit 0；改 `callback_result_format = yaml` → exit 0 且输出为 yaml 风格。
- 并**补一条真实执行 smoke**（见 D3），否则同类配置错误仍会漏网。

### [MAJOR] 门禁无"真实执行"检查，导致 D1 类缺陷漏网（假绿）
- 位置：`Makefile:26-27`（`syntax` 仅 `--syntax-check`）、`tests/skeleton/test_skeleton.sh:44-53`（同样只做 syntax-check）
- 复现：`make lint && make test` → 全绿 exit 0，但 `ansible-playbook playbooks/site.yml` exit 1（见 D1）。
- 期望：门禁能发现"配置无效以致 playbook 无法运行"。
- 实际：`--syntax-check` 不加载 stdout callback，故不报错；测试脚本也不做真实运行。
- 建议方向：在 `test_skeleton.sh`/`Makefile` 增加 `smoke` 目标，例如对 `localhost` 跑一次占位 playbook：
  `$AP -i localhost, -c local playbooks/site.yml`（或最简：校验 `ansible-config dump` 能加载配置），断言 exit 0。

### [MINOR] 测试对 `.gitignore` 的断言是弱子串匹配，可被注释行骗过
- 位置：`tests/skeleton/test_skeleton.sh:40-41`
- 复现（在副本中）：
  ```bash
  sed -i 's/^\*\.key$/# *.key/' .gitignore
  ./tests/skeleton/test_skeleton.sh      # 仍 PASS=25 FAIL=0, exit 0
  git check-ignore -q secret.key || echo "secret.key 未被忽略（危险）"   # → 危险
  ```
- 期望：规则被注释掉后测试应 FAIL。
- 实际：`grep -q '\*\.key'` 只匹配子串，`# *.key` 也命中 → 漏报。
- 建议方向：改用行为断言，如 `git check-ignore -q <探针文件>`（或 `git check-ignore -v`）验证密钥确实被忽略。

### [MINOR] `make syntax` 只对 `site.yml` 做语法检查
- 位置：`Makefile:15,26-27`（`SITE ?= playbooks/site.yml`）
- 复现：`make syntax` 不覆盖 `add-node.yml`/`upgrade.yml`（虽经我手工确认二者 syntax-check 均 exit 0）。
- 期望：入口占位全部纳入静态检查。
- 实际：仅 `site.yml`（其子 playbook 通过 `import_playbook` 间接覆盖，但 `add-node`/`upgrade` 不在其中）。
- 建议方向：`SITE` 支持多文件，或在 `syntax` 目标中对 `playbooks/*.yml` 循环校验。

### [MINOR] 默认 inventory 指向缺失的 `inventory/hosts.ini`，无 `-i` 时静默降级并伴随噪声
- 位置：`ansible.cfg:6`（`inventory = inventory/hosts.ini`），而 `inventory/hosts.ini` 被 `.gitignore:14` 忽略、仓库内不存在（示例为 `hosts.example`）。
- 复现：`$AP --syntax-check playbooks/site.yml`（不显式 `-i`）→ 三条 WARNING（`Unable to parse ... as an inventory source`、`No inventory was parsed`、`Could not match supplied host pattern: k8s_master/k8s_node`）但 exit 0。
- 期望：默认入口要么有兜底（如 `inventory = inventory/hosts.ini, inventory/hosts.example`），要么在 README/`make` 里显式提示先 `cp`。
- 实际：静默降级（exit 0，易掩盖配置问题）。
- 建议方向：`ansible.cfg` 增加 fallback 路径，或在 `Makefile` 的 `check-inventory` 前置断言 `hosts.ini` 存在并给出提示。

## 5. 非阻塞改进项（供后续吸收）
- **安全默认**：`ansible.cfg:8` `host_key_checking = False` 关闭了 SSH 主机密钥校验，存在 MITM 风险。生产/多租户环境建议默认开启，或在文档中显式声明该权衡（本任务判为可接受，记 4 分）。
- **`PYTHONPATH` 兜底副作用**：`Makefile:9-12` 当 `ANSIBLE_PLAYBOOK` 为系统路径（如 `/usr/local/bin/ansible-playbook`）时会把 `/usr/local` 写入 `PYTHONPATH`。当前环境无副作用，建议仅当命中 `$HOME/ansible/bin` 时导出。
- **`yamllint` 不覆盖 `inventory/hosts.example`**（无 `.yml/.yaml` 扩展名，属预期；如需可显式加入）。
- **`deprecation_warnings = False`**（`ansible.cfg:11`）会压制弃用告警，可能掩盖类似 D1 的迁移问题，建议保留默认或仅在有明确理由时关闭。
