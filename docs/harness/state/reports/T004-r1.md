## 4. 缺陷清单（按严重度）

> 分级口径：BLOCKER=验收项/安全致命；MAJOR=常见路径功能错误；MINOR=边缘路径或契约文字不一致；NIT=打磨项。

### [MINOR] D1 · 私钥文件「存在但不可解析」时不触发自愈，role 仍报成功
- 位置：`roles/pki/tasks/_needs_regen.yml:55-64`（`pki_needs_key` 的匹配分支要求证书与私钥**都**可读，私钥 `openssl pkey` 失败时反而判为 false）；`roles/pki/tasks/verify.yml:68-77`（只 chmod，不校验私钥可解析/匹配）。
- 复现（评估者独立构造，`indep_result.log` phase 7）：
  ```bash
  printf 'not a private key\n' > $SB/etc/kubernetes/pki/kubelet/w-two.key   # 证书仍有效
  ansible-playbook -i <inv> <indep_play> -e sandbox_root=$SB                  # rc=0
  # 实测：rc=0 changed=0 pkey_readable=no
  ```
- 期望：按契约 §5「产物……**无法解析**……重新生成」与 `tasks/main.yml:16`「损坏……→ 重签（自愈）」重建私钥并重签证书。
- 实际：`rc=0 changed=0`，`openssl pkey -in kubelet/w-two.key -noout` 失败；后续 apiserver/kubelet 会在启动时暴露 TLS 错误（假成功）。`pki_force_regen=true` 可恢复（实测 changed=53、私钥可读、证书匹配）。
- 建议方向：`pki_needs_key` 增加「私钥存在但 `pki_check_key_pubkey.rc != 0`」分支；或在 `verify.yml` 增加私钥可解析 + 证书/私钥匹配断言（fail fast 或触发重签）。同时在 A13 增补该负例。
- 影响面：仅「私钥被外部损坏/截断且证书仍有效」场景；不属于 A1–A20 枚举项，故不阻塞本轮。

### [MINOR] D2 · 选择性 tags 单跑失效（`--tags pki:ca` / `pki:cert` 直接报错）
- 位置：`roles/pki/tasks/main.yml:58-67`（include 标 `pki:ca`）、`roles/pki/tasks/cert.yml:11-16`（标 `pki:cert`），但 `roles/pki/tasks/_needs_regen.yml:28-35,55-64` 的内层任务只标 `pki:check` → 被 tag 过滤掉，`pki_needs_key` 未定义。
- 复现：
  ```bash
  ansible-playbook -i tests/pki/inventory.ini tests/pki/sandbox.yml --tags pki:ca -e pki_root_prefix=$SB
  # rc=2；ERROR: Error while evaluating conditional: 'pki_needs_key' is undefined
  ```
  日志：`/tmp/opencode/evalT004/tags_ca.log`。
- 期望：契约 §10.1 第 261 行声称「tags `pki:*` 可单跑」；`repo-conventions.md` 要求 role 内 tags 便于单跑。
- 实际：仅 `--tags pki`（全量）可用；细分 tag 会报未定义变量。
- 建议方向：给 `_needs_regen.yml` 的内层任务补上父级 tag（或在 include 上用 `apply: tags:` 合并），并加一条 `--tags pki:dirs`/`pki:ca` 的冒烟断言；若不做，则删除该声称并在 README 注明「仅支持 `--tags pki`」。

### [NIT] D3 · kubelet 证书只为 `k8s_node` 生成，master 主机默认没有
- 位置：`roles/pki/tasks/facts.yml:100`（`loop: "{{ pki_node_hosts }}"`，即 `pki_node_group` 默认 `k8s_node`）。
- 证据：独立 inventory（3 master + 2 node）产出 `kubelet/` 仅 `w-one.crt/.key`、`w-two.crt/.key`，无 `m-alpha` 等。
- 说明：契约 A2/A4 以 `k8s_node` 为 N，未要求 master kubelet，故**不构成验收失败**；但本项目中 master 也会运行 kubelet（T008/T014），届时需 `-e pki_node_group=k8s_cluster` 或扩展 role。建议在 README 明示该用法。

### [NIT] D4 · 测试构造过期证书使用 OpenSSL 3.4+ 专有参数，测试本身不可移植
- 位置：`tests/pki/test_pki_role.sh:323`（`-not_before 20190101000000Z -not_after 20200101000000Z`）。
- 说明：role 声明支持 OpenSSL 1.1.1+/3.x，但该测试参数在 3.0/1.1.1 上不存在，测试套件会在旧环境失败（当前环境 3.5.1 正常）。建议改用 `openssl req -x509 -days 0` 等可移植构造方式。

### [NIT] D5 · A15b 强制重签后只显式验了 front-proxy 一条链
- 位置：`tests/pki/test_pki_role.sh:379`。
- 说明：role 自身的 `verify.yml` 每次都会全链校验，故实际风险低；建议测试侧对全部 leaf 循环 `openssl verify`，使断言自足。
