## 4. 缺陷清单

### [BLOCKER] D1. `--check` 模式直接失败（违反幂等硬指标）

- 位置：`roles/taints/tasks/nodes.yml:21-29`（读 Node 的 command 无 `check_mode: false`）、`:37-39`（随后用 `item.stdout | from_json` 解析）、`:52-68`（写污点任务无 `when: not ansible_check_mode` 保护）。
- 复现：§1.3 的命令；`rc=2`，错误为 `from_json ... Expecting value: line 1 column 1`，`PLAY RECAP failed=1`。
- 期望：`--check` rc=0，且不产生写操作（或至少 `changed=0`）；不应因 command 被跳过而解析空 stdout。
- 实际：check 模式下 command 被跳过，注册变量无 `stdout`/为空，`set_fact` 解析失败；role 无法干跑。
- 建议方向：给只读 command（get node）加 `check_mode: false`（与 `roles/kubelet`、`roles/etcd` 等既有 role 一致）；给写任务加 `when: not ansible_check_mode`，或在 check 模式下只报告将变更；在套件中新增 B11 `--check rc=0 / changed=0 / 不写`。
- 备注：契约 §4 B7 只写“第二次 changed=0”，但 `acceptance-criteria.md` §2 明确要求 `--check` 不得异常，故按硬指标判 FAIL。若维护者认为 check 模式不属于 T013 范围，应先在契约中显式声明例外，再降级处理。

### [MAJOR] D2. 真机复验命令不可执行，role 未接入部署 playbook

- 位置：`roles/taints/README.md:55`、`docs/harness/state/contracts/T013.md:130`、`playbooks/control-plane.yml:9-11`。
- 复现：
  ```bash
  cd /opt/codes/k8s
  PYTHONPATH=/home/zhangsan/ansible /home/zhangsan/ansible/bin/ansible-playbook \
    -i tests/taints/inventory.ini playbooks/site.yml --list-tasks --tags taints
  # 只列出 control-plane / node 两个 play，tasks 为空；没有任何 taints task
  ls inventory      # 只有 hosts.example，没有文档中的 inventory/hosts.yml
  ```
- 期望：`playbooks/site.yml --tags taints` 能执行 `roles/taints`；或文档给出可执行的 ad-hoc playbook/明确标注 T016 前不可用。
- 实际：`site.yml` → `control-plane.yml` 仍是 T004–T007 的 placeholder（`playbooks/control-plane.yml:9-11`），`--tags taints` 空跑 rc=0；`inventory/hosts.yml` 不存在。契约 §5.5 的“真实集群复验步骤”因此无法执行。
- 建议方向：在 `playbooks/control-plane.yml` 加入 `role: taints`（或新增 `playbooks/taints.yml`）并补 `--tags`；同步修正 README/契约中的 inventory 路径；在 T016 之前至少提供可复制的 ad-hoc playbook。

### [MINOR] D3. A4“已 PASS role 未被修改”断言在干净树上恒真

- 位置：`tests/taints/test_taints_role.sh:309-312`。
- 复现：在干净 worktree 执行 `git diff --quiet HEAD -- roles/pki ...` 永远 rc=0；即使被测提交本身改了这些 role 也检测不到。
- 期望：能检测被测提交是否改动冻结资产。
- 实际：只检测工作区未提交改动；本轮 A4 的 PASS 是靠独立 `git show --stat 781c912` 证明的，不是测试断言。
- 建议方向：改为 `git diff --quiet <base>..HEAD -- roles/...`（base 由 `.git` 或变量传入），或 `git show --name-only --pretty=format: HEAD` 后 grep。

### [MINOR] D4. C2 宿主快照深度不足

- 位置：`tests/taints/test_taints_role.sh:156-175`、`:754-765`。
- 现象：`/etc/kubernetes` 只记录 exists/absent；`/var/lib/containerd`、`/run/containerd` 只记录 `stat %F %a`；`/etc/systemd/system` 只查两个 unit。若内容被改写但存在性/模式不变，或“创建后删除”，不会被发现。
- 建议方向：对目录做 `find -printf '%p %s %T@'` 哈希（排除易变日志），或至少在 pre-existing 场景下对 `/etc/kubernetes` 做内容哈希；文档中明确快照边界。

### [MINOR] D5. 清理可能执行宿主级 `systemctl stop kubepods.slice`

- 位置：`tests/taints/test_taints_role.sh:183-186`。
- 现象：仅当跑前 `kubepods*` 为空时，退出时执行 `sudo -n systemctl stop kubepods.slice`；这是宿主全局操作，且与契约 §2 “不 systemctl start/stop”（`contracts/T013.md:29`）字面冲突。本机跑前已有 3 个 slice，故本次未触发；干净 CI 主机上会触发。
- 建议方向：改为清理沙箱 kubelet 自己创建的 cgroup 路径，或把该例外写入契约 §5/§9；至少加日志说明为何安全。

### [MINOR] D6. `kubectl` 可执行性未显式 fail-fast

- 位置：`roles/taints/tasks/validate.yml:15`。
- 现象：只断言 `taints_kubectl` 字符串非空；契约 §3.3.6 要求“kubectl 必须可执行”。若路径不存在，会在后续 command 任务以 Ansible 错误失败，而不是 validate 阶段给出明确信息。
- 建议方向：`ansible.builtin.stat` + `stat.executable`，或 `command -v` 探测并给出 fail_msg；套件补一条负例。

### [MINOR] D7. command 字符串 join + 目标节点未做类型校验

- 位置：`roles/taints/tasks/nodes.yml:23`、`:56`、`:74`；`roles/taints/defaults/main.yml:21`。
- 现象：`cmd` 用 `join(' ')` 传入 `ansible.builtin.command`，Ansible 会用 shlex 拆分；kubeconfig 路径/tag value 含空格会被拆成多个参数。`taints_control_plane_nodes` 若被用户覆盖成字符串，`loop` 会逐字符迭代。
- 建议方向：改用 `argv` 列表形式；validate 中断言 `taints_control_plane_nodes is sequence and taints_control_plane_nodes is not string`。
