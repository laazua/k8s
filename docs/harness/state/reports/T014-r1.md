## 五、缺陷清单（分级）

### D1 [MAJOR · 非阻塞] 零影响快照「空值/`__ERROR__`」未显式 FAIL（C7 部分未落实）

- 位置：`tests/add-node/test_add_node_flow.sh:628-643`
- 现象：前置快照守卫只有 `grep -c '=' == 11` + `! grep -q '__MISSING__'`。`node1_obj`（`node_obj_hash` 在 kubectl 失败时输出**空串**）、3 个 `*_start`（`proc_starttime` 读失败为空）、以及 `tree_hash` 的 `__ERROR__` 哨兵都能通过该守卫；随后 `check_eq` 空==空 / `__ERROR__`==`__ERROR__` 会**静默 PASS**。
- 复现（我的最小复现，不需要集群）：

```bash
printf '...11 行，其中 node1_obj= / *_start= 为空，cluster_etc_kubernetes=__ERROR__...' > /tmp/opencode/t014_guard_probe.txt
bash -c "[[ \$(grep -c '=' f) -eq 11 ]] && ! grep -q '__MISSING__' f"; echo $?   # → 0（通过）
printf '' | python3 -c 'import json,sys; json.load(sys.stdin)'                    # → rc=1 且无输出（node_obj_hash 空值来源）
```

- 期望：每个键非空且不属于 `{__MISSING__,__ERROR__}`，否则 FAIL（契约 C7 原文）。
- 建议：`node_obj_hash` 失败时显式打印 `__ERROR__`；快照守卫改为逐键 `[[ -n $v ]]`；`proc_starttime` 空值 FAIL；`__ERROR__` 与 `__MISSING__` 一起拒绝。
- 影响：本次两次运行实测值均非空（`/tmp/opencode/t014_existing_pre.txt` 11 键均有值），故不影响本轮结论；但 apiserver 瞬时抖动时 C5 的 Node 对象比较会假绿。

### D2 [MAJOR · 非阻塞] 证书幂等实际靠「文件存在」短路，`pki_ca_rebuilt` 在重跑路径不载荷；无自愈

- 位置：`roles/add-node/tasks/validate.yml:200-212`、`roles/add-node/tasks/cert.yml:17/26-28/59-61`
- 现象：`add_node_already_joined` 只判「证书 + 私钥文件都存在」，一旦为真，**cert.yml 整段跳过**（含 pki `_needs_regen` 判定）。因此：
  1. `pki_ca_rebuilt: {kubernetes: false}` 在第二次及以后运行中根本不执行 → 牙齿 T2a（改成 `true`）**无红**，契约 §3.3.2/§7「证书走 pki 的 `_needs_regen`（有效且匹配 → 不动）」与实现不符；
  2. 「证书存在但已过期/损坏/由别的 CA 签发」时不会重签，日志仍打印「已加入」，随后 kubelet 无法注册（生产默认 verify=true 会以 rc≠0 暴露，但提示误导）。
- 复现：worktree 把 `kubernetes: false` 改 `true` 跑全套 → `第二次运行 changed=0` 仍 PASS（`/tmp/opencode/t014_tooth2.log` B4 段）。
- 建议：`already_joined` 改为「存在 + `openssl x509 -checkend` 通过 + 链验证到集群 CA + CN/O 匹配」；或先走 pki `_needs_regen` 得到 `pki_needs_cert` 再决定是否跳过，并把「已加入」措辞限定为「证书有效且匹配」。
- 影响：正常加节点/重跑不受影响（本轮两次运行实测 changed=0、证书哈希不变）。

### D3 [MINOR] D1 fail-fast 的「未落盘」断言空转
