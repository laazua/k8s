## 4. B1 复核：默认路径与 systemd unit 三方对齐（重点）

**代码事实**

- `roles/haproxy/defaults/main.yml:47-48`：`haproxy_config_dir/file = {{ haproxy_base_prefix }}/etc/haproxy[/haproxy.cfg]`
- `roles/keepalived/defaults/main.yml:59-60`：`keepalived_config_dir/file = {{ keepalived_base_prefix }}/etc/keepalived[/keepalived.conf]`
- `roles/haproxy/templates/systemd-dropin.conf.j2:5,8,10,12`：
  `Environment="CONFIG={{ haproxy_config_file }}"`、`ExecStartPre/ExecStart/ExecReload ... -f {{ haproxy_config_file }}`
- `roles/keepalived/templates/systemd-dropin.conf.j2:6`：
  `ExecStart={{ keepalived_binary }} --dont-fork -f {{ keepalived_config_file }}`

**独立探针（不写宿主）**：用角色 defaults 解析变量：

```
default:  H=/etc/haproxy/haproxy.cfg   K=/etc/keepalived/keepalived.conf
redirect: H=/tmp/opencode/t006r2/sandbox.2062754/redirect/etc/haproxy/haproxy.cfg
          K=/tmp/opencode/t006r2/sandbox.2062754/redirect/etc/keepalived/keepalived.conf
```

**独立渲染（沙箱）后三方对照**：

```
H render=/tmp/.../e1/etc/haproxy/haproxy.cfg
  exec  =/tmp/.../e1/etc/haproxy/haproxy.cfg
  env   =/tmp/.../e1/etc/haproxy/haproxy.cfg
K render=/tmp/.../e1/etc/keepalived/keepalived.conf
  exec  =/tmp/.../e1/etc/keepalived/keepalived.conf
```

（`/tmp/opencode/t006r2_eval_dynamic.out` R1：`PASS H 渲染路径 == ExecStart -f`、
`PASS H 渲染路径 == Environment CONFIG`、`PASS K 渲染路径 == ExecStart -f`，
以及沙箱重定向下后缀仍为约定路径。）

**发行版 unit 对照**（环境解包制品 `/tmp/opencode/t006root/usr/lib/systemd/system/`）：

- `haproxy.service`：`Environment="CONFIG=/etc/haproxy/haproxy.cfg" ...`，
  `Type=notify`，`ExecStart=/usr/sbin/haproxy -Ws -f $CONFIG -f $CFGDIR -p $PIDFILE`。
  role 默认路径与 `CONFIG` 一致；drop-in 清空 `ExecStartPre/ExecStart/ExecReload` 并只保留
  role 的 `-f`，因此不会加载 `$CFGDIR` 下的包样例。
- `keepalived.service`：`Type=notify`、`ExecStart=/usr/sbin/keepalived --dont-fork $KEEPALIVED_OPTIONS`，
  无自定义 `-f`（默认即 `/etc/keepalived/keepalived.conf`）。role drop-in 保持 `--dont-fork`
  并显式 `-f` 同一路径，与 `Type=notify` 兼容。

**反证（牙齿）**：把 drop-in 中 `{{ haproxy_config_file }}` 改为字面量 `/etc/haproxy/wrong.cfg`
（worktree），`tests/ha/test_ha_role.sh` → **rc=1，PASS=167 FAIL=19**，其中：

```
FAIL H drop-in ExecStart 显式 -f 渲染路径（同一变量）
FAIL H drop-in Environment CONFIG == 渲染路径（同一变量）
FAIL H tasks/templates 不硬编码配置路径（唯一来源是 defaults 变量）
FAIL 在 netns 中启动 role 渲染的 haproxy（ha1/ha2）
```

故 B1 的「渲染路径 == unit `-f` == 同一变量」断言具备牙齿，不是自证。

## 8. 缺陷清单

**无 BLOCKER / MAJOR。** 以下为非阻塞改进项：

1. **[MINOR] keepalived drop-in 未显式清空发行版 `ExecStartPre`/`ExecReload`**
   - 位置：`roles/keepalived/templates/systemd-dropin.conf.j2:4-6`
   - 现状：仅覆盖 `ExecStart`（本环境 EL unit 无 `ExecStartPre`，故不触发问题）。
   - 建议：与 haproxy 对称加 `ExecStartPre=` / `ExecReload=/bin/kill -HUP $MAINPID` 的空赋值，避免未来发行版 unit 变化时继承旧路径。
2. **[MINOR] `haproxy_config_dir` 未由 `haproxy_config_file` 派生**
   - 位置：`roles/haproxy/defaults/main.yml:47-48`；`roles/haproxy/tasks/config.yml:10-15`
   - 现状：覆盖 `haproxy_config_file` 到新目录时，`config_dir` 仍是 `/etc/haproxy`，模板会因父目录不存在而失败。
   - 建议：从 `haproxy_config_file | dirname` 派生，或在 validate 中断言父目录。
3. **[MINOR] 测试使用固定 netns 名与固定 `/tmp/opencode/t006_*` 日志**
   - 位置：`tests/ha/test_ha_role.sh:206-209`
   - 影响：并发执行会互踩；当前串行流程不受影响。
   - 建议：加 `$$`/随机后缀并隔离日志目录。
4. **[NIT] notify 状态日志未被仓库测试断言**
   - `keepalived` 的 `notify_master/backup/fault` 由独立评估验证（`/run/.../state.log` 出现 `master`），但 `tests/ha` 未断言；建议补 1 条。
5. **[NIT] VRRP `auth_pass` 默认固定 `k8s-ha`，配置文件 0644**
   - 位置：`roles/keepalived/defaults/main.yml:36`、`:61`
   - 建议：README 提醒 inventory 覆盖；如需更强隔离可 0640 + 组属主。
6. **[NIT] 生产语义下 haproxy 先渲染/启动，keepalived 的 VIP/VRRP 校验在后**
   - 位置：`roles/haproxy/tasks/main.yml` 与 `roles/keepalived/tasks/validate.yml`（两个 role 串联时）
   - 影响：VIP 参数错误时 haproxy 可能已启用（不影响正确性，只是部分变更）。建议 T007 编排时先做双 role 的只读 pre-flight。
