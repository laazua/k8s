### 4.2 核心数据面（不轻信套件）

- 参数确实取自渲染产物：`test_cilium_role.sh:484-487` 用 `manifest.py get-config` 读取
  `cluster-id`/`tunnel-port`/`mtu`/`cluster-pool-ipv4-cidr`，再传给 `net_pair`（`:500-524`）。
- 拓扑确实是**两个 netns**：`ip netns add ${tag}1/2` + `veth` 两端分别 `ip link set … netns`
  （`:503-507`），不是同 namespace 直连。
- 套件外独立复现（VNI=7、port=9472、MTU=1400）：
  - `ip netns list` 显示 `e1`、`e2`；`ip -n e1 route get 10.88.0.2` → `dev vxlan0`；
  - underlay `ping 192.168.77.2` OK；`ping -c2 10.88.0.2` 2/2；
  - `http.server 18082 --bind 10.88.0.2`，从 e1 `curl` 得到已知响应 `DP-OK-EVAL`；
  - VNI 反证（e2 用 VNI+1）：underlay OK，Pod IP 不通；
  - 端口反证（e2 用 9473）：underlay OK，Pod IP 不通。
- 结论：ICMP 与 HTTP 都由**真实内核 VXLAN 封装/解封装**完成；但仍是内核隧道，
  **不是** Cilium BPF/Pod 网络（与契约 §5.4 一致）。

### D1 [MINOR · 文档证据] 全量总数 1526 误写，实际 1633

- 位置：`docs/harness/state/contracts/T010.md:233`、`:280`；`docs/harness/state/state.yaml:42`；

- 复现：
  ```bash
  grep -oE '汇总: PASS=[0-9]+ FAIL=[0-9]+' /tmp/opencode/t010_r2_full.clean \
    | sed -E 's/[^0-9]+/ /g' | awk '{s+=$1; f+=$2} END{print s, f}'

  grep -c '汇总: PASS=.*FAIL=0' /tmp/opencode/t010_r2_full.clean   # 10
  ```
- 期望：`1633 PASS / 0 FAIL`；实际：文档写 `1526`。清单本身列出的 10 个计数相加即为 1633。
- 影响：不隐藏失败、不改变无回退结论；属证据表述错误。
- 建议：由 Generator 在契约/state/handoff 中改为 `1633`（Evaluator 不改契约），后续提交信息无需改写历史。

### D2 [MINOR · 测试卫生 v1.5 残余] B5 宿主快照仍含全局 vxlan 计数且采集失败静默

- 位置：`tests/cilium/test_cilium_role.sh:285-296`，尤其 `:287`
  `nsenter -t 1 -n ip -d link show type vxlan | grep -cE '^[0-9]+:'`。
- 期望（spec v1.5）：快照收敛到本任务拥有的资源；外部命令采集空值重试、耗尽显式失败并落原始输出。
- 实际：计数的是**宿主全部** VXLAN 接口（未按任务名过滤）；`host_snapshot` 用 `2>/dev/null`
  与 `|| true`，`nsenter`/`iptables-save` 失败时 `grep -c` 会得到 `0`（与真实零值不可区分），
  可能 PRE=POST 假绿；无重试。
- 本轮观察：宿主 vxlan=0，4 次均绿，未出现 flake；但这是 T009 B10 同类风险。
- 建议：改为断言“宿主无 `pos*/vni*/prt*` 或本任务 vxlan 名”的收敛集合；封装 `collect()`：
  20×0.2s 重试，耗尽 `bad` 并在 `/tmp/opencode/t010_host_diff.log` 落原始命令输出。
- 同段 `:588-589` 的 `ip -o link show` 是在套件自身 netns 内查 `vxlan0/pos*`，对子 netns
  泄漏是弱断言（真正兜底靠 `ip netns list`），可一并加强。

### D3 [MINOR · 测试卫生] 宿主进程匹配过宽

- 位置：`tests/cilium/test_cilium_role.sh:310` `pkill -f "http.server 18081"`；
  `:587` `pgrep -f '[h]ttp.server 18081'`。
- 风险：`pkill` 在宿主 PID namespace 内按命令行匹配，可能杀掉无关的 18081 进程
  （虽然 18081 是本任务在契约中声明的端口）。HTTP 进程已有 `$HTTP_PID`，无需全局 `pkill`。
- 建议：只 `kill "$HTTP_PID"`/等待其退出；断言只查该 PID 或 netns 内进程。

### D4 [非阻塞 · 真机风险] 渲染清单的 operator RBAC / CNI 安装完整性

- 位置：`roles/cilium/templates/cilium.yaml.j2:199-221`（operator ClusterRole）、`:109-175`（DaemonSet）。
- 现象：operator ClusterRole 未包含 `coordination.k8s.io/leases`（leader election 所需）与
  `events`；DaemonSet 未含 CNI 配置安装 init container / `dnsPolicy: ClusterFirstWithHostNet`。
- 影响：本环境无镜像、不运行 agent/operator，契约 §5.5/§9 已声明运行态未验证；但契约 §5.7 的
  真机 `rollout status deploy/cilium-operator` 与 Pod 网络步骤可能因此失败。
- 建议：真机验收前与官方 Cilium 1.16 chart 的 RBAC/initContainer 对齐（可作为 T011/T012 或
  T010 follow-up），并在真机复验记录中验证。

### D5 [MINOR · 覆盖] 部分变量缺少动态变体

- 现状：cluster-id / API endpoint / version 的映射由 B1 + A3 静态断言覆盖，但没有像
  geneve/native 那样的“换值再渲染”动态变体；若模板硬编码与 B1 相同的 7/192.0.2.10/1.16.3，
  静态 A3 仍会检查变量名，但动态证据弱一档。
