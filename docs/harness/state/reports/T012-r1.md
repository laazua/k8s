## 7. 缺陷清单（按严重度；均非本轮阻塞）

### [MAJOR] D1 real 模式「0/0 空集恒真」假绿
- 位置：`tests/e2e/smoke.sh:377-387`
- 复现：`tests/e2e/smoke.sh --mode real --kubeconfig /tmp/opencode/eval-fake-kubeconfig`（文件有效但 `server: https://127.0.0.1:1`）
- 期望：`全部节点 Ready（0/0）`、`kube-system 全部 Pod Running` 在节点数/查询为 0 时判 FAIL 或「无法判定」。
- 实际：两条均 PASS（`nodes=0, ready=0`；`bad_pods` 空→0），只有 `/healthz`、节点数、Pod 数、kube-dns 兜住 FAIL。
- 建议方向：`ready==nodes` 前先要求 `nodes>=E2E_EXPECT_NODES`；`bad_pods==0` 前先要求 `pods>0`，并把 `kubectl` 查询 rc 显式判 FAIL。

### [MAJOR] D2 real 模式 Job 创建失败被降级为 SKIP（掩盖 RBAC/admission/配额故障）
- 位置：`tests/e2e/smoke.sh:393-401`
- 复现：真机上以无 `create jobs` 权限的 kubeconfig 执行 `--mode real --image <img>`（或用拒绝 Job 的 admission 策略）
- 期望：`kubectl create job` 失败 → `FAIL 集群内 DNS（Job 创建失败）`。
- 实际：`SKIP 集群内 DNS（Job 创建失败，检查 --image）`，RESULT 可能仍 PASS。
- 建议方向：仅当「镜像不存在/拉取失败」这类环境受限证据明确时 SKIP；API 错误（Forbidden/Timeout/Invalid）一律 FAIL。

### [MAJOR] D3 选项缺值时无限循环（挂死）
- 位置：`tests/e2e/smoke.sh:41-50`（`--mode`/`--kubeconfig`/`--image` 均 `shift 2`）
- 复现：`timeout 5 tests/e2e/smoke.sh --mode; echo $?` → `124`；`--image` 同样；日志 0 行。
- 期望：rc=2 + usage（与未知参数一致）。
- 实际：`$#==1` 时 `shift 2` 返回非 0 且位置参数不变 → while 循环永不退出；无 `set -e` 兜底。
- 建议方向：分支内先校验 `$#>=2 && -n "${2:-}"`，否则 `printf ... >&2; exit 2`；或 `shift $(( $# >= 2 ? 2 : 1 ))`。

### [MINOR] D4 清理失败静默，且 RESULT 在 cleanup 之前打印
- 位置：`tests/e2e/smoke.sh:191-204`（`sudo -n rm -rf "$SB" || true`、`stop_proc` 全忽略错误）、`smoke.sh:416-418`（先打 RESULT，再 cleanup）
- 复现：代码审查；单跑 `smoke.sh --mode sandbox` 时 C1/C2 断言只在 meta-test 中存在，cleanup 失败不会出现在输出与退出码里。
- 期望：cleanup 失败至少一行 `FAIL 清理...` 并使 rc≠0，或把清理断言纳入 `smoke.sh` 自身。
- 实际：可能 `RESULT=PASS` 却残留进程/目录（本轮实测无残留，属潜在风险）。
- 建议方向：cleanup 内累积失败计数并在汇总前检查；RESULT 移到 cleanup 之后打印。

### [MINOR] D5 `--static-only --mode real` 强制要求 `--kubeconfig`
- 位置：`tests/e2e/smoke.sh:56-59`
- 复现：`tests/e2e/smoke.sh --static-only --mode real` → rc=2。
- 期望：static-only 不使用 kubeconfig，应允许缺省（或仅在实际执行 real 检查时校验）。
- 实际：退出 2。
- 建议方向：把 real 校验移入 `run_real()`（或加 `STATIC_ONLY -eq 0` 条件）。

### [MINOR] D6 服务 IP / CoreDNS 版本与 role 默认值双源
- 位置：`tests/e2e/smoke.sh:216`（`SVC_KUBE=10.96.0.1`）vs `roles/kube-apiserver/defaults/main.yml:107`；`smoke.sh:129`（`CD_VERSION=1.11.3`）vs `roles/cluster-addons/defaults/main.yml:56`
- 复现：改 `k8s_service_cidr` 为 `172.20.0.0/16` 后跑 sandbox → DNS 断言仍期望 `10.96.0.1` 而红（假 FAIL）；改 role 的 CoreDNS 版本后脚本仍下载旧版。
- 期望：从 role defaults/渲染产物取值，或变量化并校验一致性。
- 实际：硬编码，靠「默认值恰好相同」保持一致。
- 建议方向：优先从渲染出的 Service/Pod spec 或 `ansible-inventory` 读取；至少加一处「脚本常量 == role 默认值」自检。

### [MINOR] D7 `kubepods.slice` 清理条件反直觉

- 复现：本机跑前已有 3 个 `kubepods*` unit → 条件短路，永不停 slice；若跑前为空则停整个 slice（可能误伤在此期间宿主新建的容器）。
- 期望：只清理本次沙箱新增的 slice（按 `kubelet --root-dir`/cgroup 前缀或前后差集），或明确记录「已有宿主 kubepods 时跳过」。
- 实际：以「跑前是否有任意 kubepods unit」决定，粒度错误；本轮因 kubelet 未建 slice 未产生残留。
- 建议方向：记录前后 unit 差集，仅 stop 新增项；无新增则不调用 systemctl。

### [MINOR] D8 静态检查只验证目录/文件存在 + playbook 语法

- 复现：把 `roles/cilium/` 清空但保留目录 → `--static-only` 仍 rc=0（syntax-check 不校验 role 内容完整性）。
- 期望：至少校验 role 关键文件（tasks/main.yml、defaults、meta）或交付物 hash。

- 建议方向：把 T011 的静态断言粒度下放（关键文件清单）或复用各 suite 的静态入口。
