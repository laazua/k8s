### [MINOR] D3 `A4 changed=0` 的判定依赖「日志中最后一个 `changed=N`」，粒度偏粗
- 位置：`tests/download/test_download_role.sh:113`（`changed_of()`）与 `:145-149`
- 复现：牙齿 M3（`force: true`）→ `PASS=58 FAIL=1`，**A4 未 FAIL**；M3b（`changed_when: true`）→ A4 FAIL。
  机理：`get_url` 在 `force: yes` 下若**内容完全相同则不替换**，因此 `PLAY RECAP` 仍是 `changed=0`，
  同时 A5 的 inode/mtime 断言也不红；真正的差异（每次仍发网络请求）只由 A5 的「源不可达」断言捕获。
- 期望：破坏幂等时 `changed=0` 断言必须直接 FAIL（本轮任务书要求），且「已存在仍重下」的元数据断言应独立咬住。
- 实际：`changed_when: true`（M3b）与「先删后下」（M12）两条路径下 A4/A5 元数据断言确实 FAIL，**保护圈成立**；
  但仅 `force: true` 时 A4 不会 FAIL（不过 M3 仍被抓）。
- 建议方向：A4 改为断言「`download:fetch` 任务自身的 `changed` 为 0」或直接断言「两次运行期间源请求数为 0」，
  使「是否发网络」与「是否替换文件」两个语义各自有独立断言。**非阻塞。**

### [NIT] D4 确定性的 checksum 不符也会被 `until` 重试（浪费带宽）

- 复现：drive1 的 I4 日志（`…/indep` 沙箱 `i4.log`）：
  ```

  ```
  即一次配置错误触发 4 次完整下载尝试（mock 源端口日志确认）。
- 期望：校验失败属确定性错误，无需重试。
- 实际：按 `download_retries`（默认 3）重复尝试。
- 建议方向：把重试缩到瞬时网络错误（例如对 5xx/超时重试，对 checksum 失败直接 fail），或文档注明代价。

### [NIT] D5 `download:resolve` 的 folded-scalar 拼接可读性差
- 位置：`roles/download/tasks/main.yml:42-48`
- 说明：`_resolved: >- {{ item | combine({...}) }}` 依赖「整串模板表达式返回原生 dict」的隐式行为，
  读代码时容易被误认为字符串；且 `_name` 与 `_resolved` 的求值顺序耦合。
- 建议方向：改为 `ansible.builtin.set_fact` 的多行 dict，或 `_resolved: "{{ … }}"` 单行并加注释。
