## 1. 目标（本任务交付什么）
`roles/download`：通用制品获取 role —— 按「URL + **强制 sha256**」下载任意二进制/依赖，
支持 `proxy_env`（`http_proxy` / `https_proxy` / `no_proxy`）、本地缓存/制品目录（已存在且 hash
相符则**跳过不改动**）、超时与重试，全部行为变量化（禁止硬编码）。

## 2. 非目标（明确不做什么）
- 不实现具体 k8s 组件的制品清单（真实 url/sha256 由 T007/T008 等以变量注入；本 role 只提供机制）。
- 不安装/解包制品，不做 GPG 签名校验（本任务只要求 sha256）。
- 不接入 `playbooks/site.yml`（编排由后续任务负责）。

## 5. 幂等与例外
- 幂等期望：同参数连跑两次，第二次 `changed=0`；已存在且 hash 相符的制品**不被触碰**（inode/mtime/size 不变）。
- **明确的非幂等例外（有意设计）**：制品**已存在但 sha256 与期望不符**时，本 role 视为缓存损坏并**重新下载**
  （`changed=1`）。理由：宁可自愈也不要静默使用被污染/半截的制品。该例外由 `download_force` 之外的逻辑触发，
  与「已存在则跳过」不冲突——跳过的前提是 **hash 相符**。此语义将在 README 与本契约声明。
- **受限声明（对应 spec R1）**：
  - 本环境 **docker registry 不可达、无可用镜像**，故**不使用 molecule/testinfra**；改用本地 mock HTTP 源
    与 mock 代理做真实验证（真实执行 role、真实落盘、真实 HTTP 交互）。
  - 本环境**禁止外网访问**，故**真实 k8s 官方制品（dl.k8s.io 等）的下载与校验无法在此验证**；
    role 只保证「给定 url+sha256 的机制正确」。真实制品需在联网/真机环境按 §6 复验。
  - TLS 证书校验（`validate_certs`）仅做变量化与语法断言，**未对真实 HTTPS 站点验证**。
- 全部测试离线、可重复：同一命令连跑两次结果一致。

## 7. 风险与假设
- 假设：`get_url` 的 `checksum` 会对**落盘后**的制品做 sha256 校验，失败时不把文件移入 `dest`；
  已实测确认（见 §9 实验证据 E0）。
- 假设：`get_url` 通过 `environment` 接收的 `http_proxy`/`no_proxy` 由 urllib 生效；已实测确认（E0）。
- 风险：真实 HTTPS/官方站的证书与重定向行为未验证（§5 已声明）；`no_proxy` 对 HTTPS 目标未验证。

## 10. 实现说明与实验证据

### 10.1 交付物
- `roles/download/{defaults,tasks,handlers,meta,README.md}`：
  `download:validate`（必填校验，禁止省略 sha256）→ `download:resolve`（归一化 dest/mode）
  → `download:dirs` → `download:fetch`（`get_url` + `checksum: sha256:<hex>` + `environment: {{ download_proxy_env }}`
  + `timeout` + `until/retries/delay`）→ `download:verify`（落盘后独立复验 sha256）。
- `tests/download/`：`mock_servers.py`（origin/flaky/proxy 三合一，随机端口写 JSON）、
  `fixtures/{hello,flaky}.bin`、`run_role.yml`、`test_download_role.sh`（59 条断言）。
- `Makefile`：`test` 目标纳入新套件，新增 `test-download`。

### 10.2 前置实验（E0，确定实现方案，非事后补证）
| 实验 | 结论 |
| --- | --- |
| `get_url` + 正确 checksum | 首次 `changed=1`；制品已存在且 hash 相符时再次运行 `changed=0`（且 mtime 不变） |
| `get_url` + 错误 checksum | 任务 **失败**（exit 2），`dest` **不存在**，无半成品残留（临时文件在远端 tmp 目录，不落 `dest`） |
| `get_url` + `environment: {http_proxy}` | 请求确实到达代理（代理日志出现绝对 URI 请求行） |
| `get_url` + `environment: {http_proxy, no_proxy=127.0.0.1}` | 请求**绕过**代理（代理日志为空），下载仍成功 |
| `get_url` + `until` + `loop` | 逐项重试生效（源 503 → 自动重试 → 成功） |

### 10.4 其它设计说明
- 「已存在但 sha256 不符」→ 重新下载（自愈），已在 §5 声明为有意的 `changed` 例外。
- 「已存在且 hash 相符但 mode/属主不符」→ `get_url` 仅修正属性（`changed=1`）。故测试用例 A5 与 A2 使用
  相同 `mode`，以严格断言「跳过不改动」。
- `omit`（属主置空）无法经 `set_fact` 存续，故 owner/group 在 `download:fetch` 的模块参数层解析
  （`item.owner | default(download_file_owner)`），已在 tasks 中注释。
- 测试失败时**保留沙箱目录**并把端口写入 `/tmp/opencode/t003_last_ports.json` 供排障；成功则清理。
- 本 role **未接入** `playbooks/site.yml`；`tests/skeleton`、`tests/base`、`roles/base` 未改动。
