## 3. 依赖、环境事实与设计取舍

### 3.1 依赖

- 缺陷来源：`docs/harness/state/reports/T015-r1.md` §五 D1–D8。

### 3.2 设计取舍（请 Evaluator 重点判断）
1. **E7/E8 的 bin 目录放真实旧二进制**（`$SB/usr/local/bin/kube-apiserver` 的 1.31.0 副本），而不是
   新造假二进制：只有这样才能让 `backup.yml` 通过、真正走到 `binaries` 阶段（D1 的根因是 backup 先失败）。
2. **E8 的 `upgrade_known_sha256` 必须以整份 JSON 注入**（`-e '{"upgrade_known_sha256":{...}}'`）。
   T015 用的 `-e upgrade_known_sha256={"1.32.13":...}` 会被当成**字符串**，`[...][item]` 取不到值 →
   断言「目标版本 sha256 未固定」先失败。这正是 D1 掩盖的第二个假绿：修好 bin 目录后立刻暴露。
   本任务同时加了两条守卫断言（注入生效 / 未因未固定提前失败）。
3. **回滚证据按任务结果行判定**（`task_status`/`task_changed` 取 `TASK [...]` 之后的首个结果行），
   并用两条**合成日志**自检：`skipping:` 块必须判否、`changed:` 块必须判是。自检不是恒真，
   它复现了旧式 `grep 任务名` 的假绿路径。
4. **D5 用隔离的 fake 备份根**做负例（`upgrade_needed=false` + `retention=1` → 目录数不变、changed=0），
   再用「探针组件回退」构造正例（`upgrade_version_probe_component=kube-scheduler` → `upgrade_needed=true`
   时仍按保留数裁剪）。正例覆盖 `upgrade_needed` 条件不会误杀功能。
5. D3 的 `kubepods` 断言改为「本次新建数 = 成功停止数 + 无失败项 + 宿主 loaded 集合恢复到测试前」，
   并打印本次新建数（沙箱实测 **0**，因无镜像→无 Pod→无新建 slice；真实载荷是 loaded 集合比较）。
6. D6 的 `item` 告警不止 `backup.yml:67,78`：`rollback.yml:132,153` 在 upgrade 路径上被判 `skipping:`
   但任务名仍被模板化 → 同样告警。四处任务名一并去掉 `item`。

## 5. 受限声明（沿用 T015 §5，并补 D7/D8 口径）

1. **单宿主单节点**（cp1 + node1）；多节点 `serial: 1` 滚动、全部节点 Ready=True 未验证。
2. **无 CNI/镜像** → node1 `Ready=False`、系统 Pod 不 Running（`SKIP=2` 单列，不计 PASS）。
3. **无 systemd** → `upgrade_manage_service=true` 的 stop/start/handler 路径未执行。
4. **etcd 单成员**；3 成员滚动/restore 后集群重建未验证。**多成员回滚必须显式覆盖**
   `upgrade_rollback_etcd_member_name=<inventory_hostname>` /
   `upgrade_rollback_etcd_initial_peer_url=https://<peer_ip>:2380` /
   `upgrade_rollback_etcd_initial_cluster`（D7，已写入 `roles/upgrade/README.md`、
   `tests/upgrade/README.md`、`defaults` 注释、T015 契约 §5）。
5. **D5 负例只在 fake 备份根上执行**（隔离，不破坏真实回滚备份）；真实根上的等价性由 C1
   「第二次运行未新增备份目录」与正例裁剪共同覆盖。
6. **kubepods 新建 slice 数 = 0**（无 Pod），D3 的「只停本次新建」由选集合逻辑自检 + loaded 集合
   恢复 + 无失败项三条证据承担，未在真机 Pod 场景复验。
7. **D8 口径**：PKI/kubeconfig/kubelet.conf 哈希相等是**必然**（升级不改它们），只作辅助证据；
   主证据 = 二进制哈希 + apiserver `/version` + 升级期 ConfigMap 消失（均已在本套件真实断言）。
8. 真机复验步骤见 T015 契约 §5（升级/回滚命令 + 多成员覆盖项）。
