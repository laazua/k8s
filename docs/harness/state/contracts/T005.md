## 1. 目标（本任务交付什么）
`roles/etcd`：以**官方二进制 + systemd unit** 部署一个**奇数成员**的 etcd 集群；成员清单来自
inventory 的 `etcd` 分组（可显式覆盖），端口 / 数据目录 / 集群 token / TLS 开关与证书路径全部变量化。
role 负责：奇数成员 fail-fast 校验、二进制获取（复用 `download`：URL + 强制 sha256 + 代理 + 缓存）、
安装、数据目录、systemd unit 渲染、（生产）启用/启动服务、unit/二进制变更时重启。

可判定交付：
- 3 成员 etcd 真实运行，`etcdctl endpoint health` 全部 healthy；`member list` 恰为 3；
- 重启任一成员后集群恢复 healthy（quorum 2/3 期间仍可读写）；
- 偶数成员时 role **fail-fast** 并给出明确错误；
- 同参数连跑第二次 `changed=0`，unit/二进制 sha256 不变；配置变更才通知重启 handler。

## 5. 幂等与受限声明（对应 spec R1 / C13）

### 5.1 权限模型（B1：非 root 服务用户读证书；B2：系统路径不可被服务用户改写）
- **不修改 pki 源**：`roles/pki` 仍以 `root:root 0700` 目录、`0600` 私钥产出；etcd role 不 chown/chmod pki 叶子，
  避免削弱 kube-apiserver 等其它消费者，也避免与 pki 每次重跑时的权限重置冲突。
- **证书分发**：`etcd:certs` 把 `ca.crt`、`server.crt|key`、`peer.crt|key` 复制到 `etcd_pki_share_dir`
  （默认 `/etc/etcd/pki`）：父目录 `root:root 0755`、分发目录 `root:<etcd 组> 0750`、
  证书 `0644`、私钥 `0640`（组可读、others 不可、服务用户**不可改写**）。
  unit 使用 `Group=<etcd 组>` + `SupplementaryGroups=<etcd 组>` 取得组读权限；
  `etcd_runtime_*` 指向分发目录，unit 不再引用 pki 源 `0600` 私钥。role 内用 `stat`/`assert` 复核私钥 uid=0 且 mode=0640。
- **属主三段式（删除单一 `etcd_file_owner`）**：
  1. `etcd_root_owner/group`（root）：unit 目录/文件、二进制、制品/解包目录、分发父目录；
  2. `etcd_data_owner/group`（服务用户）：成员数据目录 `0700`；
  3. `etcd_cert_owner/group`（root + 服务组）：证书分发目录。
- **非 root 真实验证**：测试以 `become: true` 应用上述生产属主，再以 `setpriv --reuid <非0> --regid <非0>
  --clear-groups` 从 unit `ExecStart` 拉起 3 个 etcd；断言进程 uid 非 0、服务 uid 可读分发私钥、
  不可读 pki 源私钥。**不再用「测试与 etcd 同用户 + `pki_file_owner: omit`」掩盖 B1**。
- **B2 宿主保护**：测试前后对宿主 `/etc/systemd/system`、`/usr/local/bin` 做 `root:root 0755` 断言；
  role 所有系统路径写入都用 `etcd_root_owner/group`，unit 内容变化才 notify。

### 5.2 滚动重启（D3）
- handler `etcd:restart` 执行 `tasks/rolling_restart.yml`：`throttle: 1` 使跨主机重启串行；
  每个成员重启后 `wait_member_healthy.yml` 先 `until` 等本成员 `endpoint health` 成功，
  再查 `endpoint health --cluster` 并要求 healthy 端点数 `>= etcd_quorum`（多数派）。
  任一失败立即 assert 中止，**不会**继续重启下一个成员（避免丢 quorum）。
- 生产仍建议 play 层 `serial: 1` 作为更强保证；本 role 的 throttle + health/quorum 闸门是第二道防线。
- 受测环境无真实 systemd：测试通过 `etcd_service_restart_argv`（默认 `[]`，生产留空）注入一个
  **真实 kill + 从 unit 重新拉起** 的钩子，验证滚动顺序与 quorum 闸门；这**不**等于验证 systemd。

### 5.3 幂等与其它受限项
- **幂等期望**：同参数连跑两次，第二次 `changed=0`；unit 模板与二进制 `copy` 仅在内容变化时 changed。
- **重启触发判定**：`template` / `copy` 任务 `notify: etcd:restart`，handler 只在单元、二进制或分发证书内容变化时触发；
  配置未变时 handler 根本不会被通知。测试用「unit sha256 + PLAY RECAP + 日志有无 `RUNNING HANDLER`」判定。
- **受限项 1（systemd 副作用）**：本环境是共享开发机，**禁止**真实 `systemctl daemon-reload/enable/start`，
  **禁止**写宿主 `/etc/systemd/system`、**禁止**占用 2379/2380。role 的 unit 目录 `etcd_unit_dir` 可重定向
  （默认 `/etc/systemd/system`，测试指向沙箱），服务管理由 `etcd_manage_service`（默认 true）控制；
  测试置 false，仅渲染 unit 并断言内容。**未验证**：systemd 真正拉起/重启 etcd。
  滚动重启的 systemd 分支（`ansible.builtin.systemd` + `throttle: 1`）同样未在真实 systemd 下验证。真机复验步骤见 §6.2。
- **受限项 2（单机多实例代替多机）**：用 `etcd_instance_layout: co-located` 在同一台机器上启动 3 个真实
  etcd 进程（独立 `--name`/`--data-dir`/高位端口），以真实 `etcdctl` 做健康、成员、leader、读写与故障恢复断言。
  **未验证**：跨主机网络、真实 systemd 托管、VIP/防火墙。`throttle: 1` 的单机验证只能证明串行与闸门逻辑，
  多主机并发语义需真机复验。真机复验步骤见 §6.2。
- **受限项 3（TLS 验证）**：TLS 默认 `true`，复用 T004 生成的 etcd CA/server/peer 证书；测试用真实 TLS +
  `--client-cert-auth` 的 3 成员集群（客户端证书 = `apiserver-etcd-client`），并用 `etcd_tls_enabled=false`
  另跑一个真实 3 成员 HTTP 集群验证开关。证书 SAN 由 pki role 从 inventory 推导，测试为 `127.0.0.1`。
- **有意的 changed 例外**：制品缓存损坏（sha256 不符）时重新下载；unit/二进制/证书内容变化时 changed 并触发 handler。
- 全部动态测试不依赖外网：首次把官方 tarball 缓存到 `/tmp/opencode/etcd-cache`（可用 `ETCD_TEST_CACHE` 覆盖），
  之后预置到沙箱制品目录，role 走 `download` 的离线缓存命中路径。

## 7. 风险与假设
- 假设目标机可访问 `storage.googleapis.com`，或已把 tarball 预置到 `k8s_artifact_dir` / 配好代理。
- 假设 etcd 3.5.x 的 systemd `Type=notify` 行为稳定；更高版本仍可变量化切换（`etcd_version`）。
- 风险：单机多实例测试对端口占用敏感（固定高位端口）；测试启动前检查端口，停止后等待释放。
- 风险：`kill -9` 后 leader 选举需要数秒；测试用重试循环（非固定 sleep）等待 quorum/healthy。
- 风险：`download` role 的缓存命中依赖 sha256 一致；默认 sha256 已按官方 tarball 实测固定。
