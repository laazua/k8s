# 任务契约 · T013

- 任务标题：调度约束（业务仅落 node）
- 契约状态：`ready_for_eval`
- 负责人（Generator）：harness-generator（子代理会话）
- 复核（Evaluator）：harness-evaluator
- 更新时间：2026-11-12

## 1. 目标（本任务交付什么）

交付 `roles/taints`：把控制面节点真实标记为「仅控制面」——

1. 给 `[k8s_master]` 节点写入可配置的 `NoSchedule`（默认 `node-role.kubernetes.io/control-plane:NoSchedule`）污点；
2. 给同一批节点写入角色标签（默认 `node-role.kubernetes.io/control-plane`）；
3. 全程经**真实 Kubernetes API** 写入并可读回；重复执行为幂等（第二次 `changed=0`）。

同时交付 `tests/taints/` 真实调度验收套件：在沙箱内拉起真实 etcd / kube-apiserver /
kube-controller-manager / kube-scheduler / containerd / kubelet，创建**不带 toleration** 的
示例 Deployment（默认 3 副本），断言全部副本 `spec.nodeName` 落在 worker 节点、0 个落在
合成的控制面节点对象上。

## 2. 非目标（明确不做什么）

- 不实现节点加入/升级（T014/T015），不实现 CNI/镜像分发（T010/T011）。
- 不创建真正可运行的业务 Pod（无镜像）；只断言**调度绑定**（`spec.nodeName`），
  不把 Pod Running 作为验收。
- 不修改 `spec.md` / `roadmap.md` 验收定义，不修改已 PASS 的 role。
- 不改动 `roles/base` 或其它 role 的既有行为；独立 `roles/taints`。
- 不在宿主写 `/etc/kubernetes`、`/etc/systemd/system`，不 `systemctl start/stop`；
  不占默认 6443/10250；kubelet 的 `kernel.panic*` 与 `kubepods.slice` 退出恢复。

### 3.3 设计取舍（需 Evaluator 注意）

1. **master 节点对象为合成对象**：沙箱只跑一个真实 kubelet（`node1`）。控制面节点 `cp1`
   由 `tests/taints/sandbox_control_plane.yml` 用 `kubectl apply` 创建 Node 对象
   （`kubernetes.io/hostname=cp1`，初始无污点/无控制面标签），再通过
   `kubectl replace --subresource=status` 注入 capacity/allocatable（cpu=16）与
   `Ready=False` 条件，使真实 scheduler 把它视为可行候选；**污点/标签仍由 role 经真实
   API 写入并读回**。这保证「调度候选集」判定真实，但不声称 cp1 有真实 kubelet。
2. **kube-controller-manager 只启用必要控制器**：
   `--controllers=deployment,replicaset,serviceaccount`，并关闭 leader election。
   目的：让 Deployment 真实产生 Pod；同时**关闭 nodelifecycle**，避免 `node1`
   因无 CNI（Ready=False）被自动打 `node.kubernetes.io/not-ready:NoSchedule` 而无法作为
   调度目标。调度绑定与 Ready 状态无关，验收只断言 `spec.nodeName`。
   另在沙箱 apiserver 禁用 `TaintNodesByCondition` 准入插件（默认启用）——它会
   在 Node 创建时直接写入 `not-ready` 污点（本环境 nodelifecycle 已关闭，无人清除），
   会污染「仅观测控制面污点」的判定。真实集群该插件与 nodelifecycle 共存，节点
   Ready 后污点会被清除，不影响本任务结论。
3. **牙齿设计**：先断言「带污点时，`nodeSelector: kubernetes.io/hostname=cp1` 且无 toleration
   的 Pod 停留 Pending，事件含 untolerated taint」；再临时移除污点，创建同类 Pod，
   断言其被真实绑定到 `cp1`，证明「没有污点就会落 master」；最后重跑 role 恢复污点。
4. **role 只增不删**：`roles/taints` 只确保目标污点/标签存在，不负责清除历史污点；
   测试用 `kubectl taint ...-` 做牙齿反证后由 role 重新写入。
5. **幂等实现**：先 `kubectl get node -o json` 读回现状，仅在缺失/值不一致时执行
   `kubectl taint/label --overwrite`；第二次运行全部 skip → `changed=0`。
6. **fail-fast**：effect 必须 ∈ `{NoSchedule, NoExecute, PreferNoSchedule}`；非
   `[k8s_master]` 主机拒绝执行；kubeconfig 必须存在；kubectl 必须可执行。

### 3.4 方案选择：独立 `roles/taints`（而非并入 base 的 tag）

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 独立 `roles/taints` | 单一职责；可单独 `--tags taints` 复验/重跑；不触碰已 PASS 的 `roles/base`；测试可只调用该 role | 多一个 role 目录 | **采用** |
| B. 并入 `roles/base` 的独立 tag | 少一个 role | 需改已 PASS 资产，回归面变大；tag 与 base 其它任务共享 handler/变量，幂等边界不清 | 不采用 |

## 5. 受限声明（对应 spec R1 v1.4 / C13）

1. **可调度 Pod 从未真正 Running**：无镜像，Pod 只完成调度绑定（`spec.nodeName`），
   随后 `ErrImagePull`；这不影响「业务仅落 node」的调度判定。
2. **master 节点对象为合成**：`cp1` 无真实 kubelet，只有真实 Node 对象 + 真实污点；
   真实多控制面主机注册未验证。
3. **真实多主机故障域未验证**：单 worker + 单合成 master；不覆盖真实多 node 打散。
4. **真实 kube-controller-manager 仅启用必要控制器**：nodelifecycle/nodeipam 等未启用；
   真实集群默认控制器组合下 Node NotReady 污点会参与调度（真机验收应观察）。
5. **真机复验步骤**：

```bash
# 0) 前置：控制面已引导完成，/etc/kubernetes/admin.conf 存在（roles/cluster-addons）
cp inventory/hosts.example inventory/hosts.yml    # 仓库只提供示例，按实际主机填写

# 1) 真实集群部署完成后（控制面 kubelet 已注册），只跑调度约束 role
ansible-playbook -i inventory/hosts.yml playbooks/taints.yml --tags taints
kubectl get nodes -o json | jq '.items[] | {name:.metadata.name,
  taints:.spec.taints, labels:.metadata.labels}'
# 期望：k8s_master 节点有 NoSchedule 污点 + control-plane 标签

# 2) 无 toleration 工作负载
kubectl create deployment t013-real --image=<可达镜像> --replicas=3
kubectl get pods -o wide
# 期望：3/3 落在 node；0 个落在 master；Pod 可 Running（有镜像时）
```

## 9. 诚实记录（环境因素、近似与未验证项）

1. **kubelet DiskPressure 阈值调整（测试环境适配，非弱化验收）**：宿主根盘可用约 12.9%，
