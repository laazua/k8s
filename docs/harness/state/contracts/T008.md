# 任务契约 · T008

- 任务标题：运行时与节点组件 role（containerd / kubelet，含 runc、CNI plugins、cgroup driver=systemd）
- 契约状态：`ready_for_eval`（未自判 PASS，等 Evaluator r1）
- 负责人（Generator）：harness-generator
- 复核（Evaluator）：harness-evaluator
- 更新时间：2026-10-27

## 1. 目标（本任务交付什么）

两个可独立执行的 Ansible role，用**官方二进制 + systemd**（非 kubeadm、非容器）拉起节点运行时：

- `roles/containerd`
  - 安装官方 `containerd` 发行包（强制 sha256；复用 `roles/download` 缓存/代理）。
  - 安装 `runc`（CRI runtime 依赖）与官方 `CNI plugins`（bridge/host-local/loopback/portmap/tuning）。
  - 渲染 `config.toml`：**`SystemdCgroup = true`**、可配置 root/state/socket、CNI bin/conf 目录、
    pause 镜像；containerd 1.x / 2.x 配置语法按版本分支。
  - 渲染 systemd unit（`Restart=always`、`LimitNOFILE`、`Delegate=yes`、`KillMode=mixed`、
    `After=network-online.target`、`WantedBy=multi-user.target`）。
  - 可选安装 `crictl`（用于 CRI 端点自检/运维）。
- `roles/kubelet`
  - 安装官方 `kubelet` 二进制（强制 sha256；复用 `roles/download`）。
  - **消费 T004 PKI 签发的 kubelet 客户端证书**（`CN=system:node:<node>`、`O=system:nodes`），
    校验身份/链/私钥匹配后渲染 `kubelet.conf`（0600 root:root，证书内嵌）。
  - 渲染 `KubeletConfiguration`：`cgroupDriver=systemd`、`containerRuntimeEndpoint` 指向
    containerd、`authentication.anonymous.enabled=false`、`authorization.mode=Webhook`、
    `failSwapOn` 可配置；kubelet serving 证书复用同一张 kubernetes-ca 签发的 kubelet 证书
    （提供 T007 N1 所需的 kubelet serving CA）。
  - 渲染 systemd unit 并用 `--container-runtime-endpoint`、`--cgroup-driver=systemd` 等 flag
    显式接线；不占用默认 10250（端口可配置，测试用 20250/20248）。
- 全部版本/架构/URL/sha256/路径/端口/flag **变量化且有默认**；不硬编码。

## 2. 非目标（明确不做什么）

- 不接入 `playbooks/site.yml`；不新建/修改节点编排 playbook（T012）。
- 不改已 PASS 的 `roles/{base,download,pki,etcd,haproxy,keepalived,kube-apiserver,
  kube-controller-manager,kube-scheduler}`。
- 不改已 PASS 的 tests，**唯一例外**：按 T007-r3 要求顺手修
  `tests/control-plane/test_control_plane_roles.sh` 的 M6（冷缓存自举顺序）与 N5（PYTHONPATH 拼接）。
- 不实现 kube-proxy / Cilium / CoreDNS / RBAC 附加对象（T009–T011）。
- 不拉取任何容器镜像（docker registry 不可达）；`crictl info` 与节点注册不需要镜像。
- 不在共享开发机写 `/etc/systemd/system`、不 `systemctl enable/start`、不写
  `/etc/containerd`、`/var/lib/{containerd,kubelet}`、不占默认 6443/10250。
- 不修改 kube-apiserver role 以打开 `--kubelet-certificate-authority`（见 §5.4）。

## 3. 依赖、环境事实与设计取舍

### 3.1 依赖
- T002（base）：内核模块/sysctl/swap 基线（生产由 base role 关闭 swap）。
- T003（download）：缓存/代理/强制 sha256。
- T004（pki）：`ca.crt` + 每节点 `kubelet/<node>.crt|key`

- T005/T006/T007（已 PASS）：真实 etcd 与 kube-apiserver，用于节点注册动态验证。

### 3.3 设计取舍（需 Evaluator 注意）
1. **kubelet 证书来源**：不在 kubelet role 内重复 openssl 签名逻辑；由 T004 `roles/pki`
   按 `[k8s_node]` 分组为每节点签发，kubelet role **只消费并强校验**
   （CN/组织/链/私钥匹配，任一不符 fail-fast）。测试 inventory 显式声明 `[k8s_node] node1`。
2. **kubelet serving 证书**：复用同一张 kubernetes-ca 签发的 kubelet 证书（含 `serverAuth`），
   通过 `tlsCertFile`/`tlsPrivateKeyFile` 指定。这样 apiserver 侧未来可直接用
   `--kubelet-certificate-authority=<kubernetes-ca>`（T007 N1 的前置条件），但本任务
   **不修改** 已 PASS 的 kube-apiserver role（见 §5.4）。
3. **cgroup driver 单一来源**：`container_runtime_cgroup_driver`（group_vars，默认 `systemd`）。
   containerd 与 kubelet 各自断言自身生效值等于该全局值，且当对方的 role 变量存在时交叉断言；
   不一致立即失败（不渲染任何 unit）。
4. **containerd 配置版本分支**：`containerd_version >= 2.0.0` 用 config `version = 3`
   （`io.containerd.cri.v1.runtime` / `io.containerd.cri.v1.images`）；1.x 用 `version = 2`
   （`io.containerd.grpc.v1.cri`）。测试固定 2.0.0。
5. **systemd 进程用户默认 root**：containerd/kubelet 需要读 0600 私钥与操作 cgroup；
   `containerd_user`/`kubelet_user` 可覆盖（非 root 需自行分发凭据，属后续任务）。
6. **端口**：kubelet `port`/`healthzPort` 全部变量化；测试用 20250/20248，避免占用宿主 10250/10248。
7. **failSwapOn**：默认 `true`（生产正确默认）；测试显式 `false`，因为禁止在共享开发机
   `swapoff`（base role 的真实语义由 T002 覆盖）。

## 5. 受限声明（对应 spec R1 / C13）

### 5.1 systemd active/enabled 未在宿主真实执行（受限）
共享开发机禁止 `systemctl enable/start`、不写 `/etc/systemd/system`。因此：
1. role 的 `service.yml` 使用 `ansible.builtin.systemd`（`enabled`/`state`/`daemon_reload` 可配置），
   默认 `true/started`；handler `daemon_reload` + `restart`；
2. unit 渲染到沙箱并断言全部关键项；
3. **用 unit 的 ExecStart 真实拉起 containerd/kubelet**，证明 unit 可直接执行；
4. 真机复验步骤见 §5.5。

### 5.2 节点 NotReady（CNI 未就绪）是**预期**
本任务不含 CNI（Cilium 属 T010）。kubelet 注册节点后 `Ready` 很可能为 `False`，
reason 通常为 `NetworkPluginNotReady` / `KubeletNotReady`。测试断言：
- 节点对象存在且名称正确；
- Ready 条件存在；
- 若 Ready=False，reason 非空且记录到日志/报告（不把 NotReady 当失败）。
`Ready=True` 属 T010 验收。

### 5.3 未拉取镜像 / 未运行容器
docker registry 不可达，且本任务不需要镜像。`crictl info` 的 CRI 端点连通与
`crictl version` 足以证明运行时可用；`crictl ps`/Pod 生命周期属 T010/T011。

### 5.4 kube-apiserver 的 `--kubelet-certificate-authority` 未打开
T007 N1 约定「T008 提供 kubelet serving CA 后打开」。本任务已让 kubelet serving 证书由
kubernetes-ca 签发（`tlsCertFile`/`tlsPrivateKeyFile` 指向 PKI kubelet 证书），
但**不修改**已 PASS 的 kube-apiserver role。真机复验时可显式加：
```bash
--kubelet-certificate-authority=/etc/kubernetes/pki/ca.crt
```
该 flag 的默认开启与端到端验证留给后续编排任务（T012/T014），避免本任务改 PASS 资产。

### 5.5 真机复验步骤（必做，目标真机执行）

### 5.6 kubelet 的宿主级副作用（快照 + 恢复）

`kubelet` 以 root 启动时会写两个**非命名空间隔离**的宿主状态：

1. `kernel.panic=10`、`kernel.panic_on_oops=1`（全局 sysctl）；
2. 通过 systemd 创建 `kubepods.slice` / `kubepods-besteffort.slice` / `kubepods-burstable.slice`
   （systemd cgroup driver 的宿主级 slice）。

测试在启动 kubelet 前快照 `kernel.panic*` 与 `kubepods*` slice 列表；在 trap 与 B8 中
**恢复原值/停止本次创建的 slice**，并断言前后一致（B8 两条新断言）。这是清理本测试自身产物，
不是产品行为；真机上这些值本应由 kubelet 持久化（属预期）。

### 6.2 测试断言修正（诚实记录，非放宽）

实现过程中发现**原测试自身**有 3 处与真实语法/真实输出不符，已修正（不是为了让实现通过而放宽）：

1. **A4 containerd config 模板**：原断言要求模板出现字面量 `version = 3`、`root = {{ ... }}`
   （无引号）、`sandbox = ...`。但 TOML 字符串必须带引号，且 A2 禁止字面量版本
   （必须变量化）。改为断言 `version = {{ containerd_config_version }}`、
   `root = '{{ containerd_root_dir }}'` 等；**渲染结果**由 B3 对真实 `config.toml`
   断言（`^version = 3`、`root = '<sandbox>'`、`SystemdCgroup = true` 等）。
2. **B3 `crictl info`**：containerd 2.x 的 `crictl info` 不再返回顶层
   `runtimeName`/`runtimeVersion`（1.x 才有）。改为断言
   `status.conditions[RuntimeReady]=true` + `runtimeHandlers` 含 `runc`；
   运行时名称/版本仍由 `crictl version`（`RuntimeName`/`RuntimeVersion`）断言。
3. **B8 清理**：`stop_proc` 由 `SIGKILL` 改为先 `SIGTERM`（containerd 需优雅退出才 unlink
   socket），并新增 kubelet 全局副作用（`kernel.panic*`、`kubepods*.slice`）的快照/恢复断言
   （见 §5.6）。
4. **A2「无硬编码下载 URL」双重否定**：原写法
   `check_not ... bash -c "! grep -rqE 'https?://' ..."`，而 `check_not` 本身已按
   “命令失败=通过”判定；`!` 又把结果翻正，导致**即使没有 URL 也判 FAIL**（假阴性）。
   改为与其余 `check_not` 一致的直接 `grep` 调用（语义不变、判定方向修正）。
5. **B8「进程已全部退出」自匹配**：原写法用
   `pgrep -f "$SB/usr/local/bin/kubelet"`，而 `pgrep -f` 匹配整条 cmdline，
   **执行断言的 `bash -c` 自身**就含该路径字符串 → 恒定命中 → 恒定 FAIL（实测确认：
   对不存在的路径 `pgrep -f` 仍 rc=0）。改为新增 `proc_alive()`：遍历 `/proc/<pid>/exe`
   的 `readlink` 与目标二进制 realpath 精确比对，既消除自匹配，也比 cmdline 匹配更严格
   （不会把“命令行里恰好提到该路径”的无关进程算作存活）。
