## 1. 目标（本任务交付什么）
`roles/pki`：**不依赖外网、不依赖 kubeadm** 的自建 PKI role，为二进制部署生成**全套证书**：

| 组件 | 产物（默认路径，可由 `pki_dir` 重定向） | 签发者 |
| --- | --- | --- |
| CA | `ca.crt` / `ca.key` | 自签 |
| apiserver | `apiserver.crt` / `apiserver.key` | kubernetes-ca |
| kubelet（每节点一份） | `kubelet/<node>.crt` / `<node>.key` | kubernetes-ca |
| admin（kubeconfig 用客户端证书） | `admin.crt` / `admin.key` | kubernetes-ca |
| front-proxy CA + client | `front-proxy-ca.crt/.key`、`front-proxy-client.crt/.key` | front-proxy-ca |
| etcd CA | `etcd/ca.crt` / `etcd/ca.key` | 自签 |
| etcd server / peer | `etcd/server.crt`、`etcd/peer.crt`（+key） | etcd-ca |
| apiserver→etcd 客户端 | `apiserver-etcd-client.crt` / `.key` | etcd-ca |
| ServiceAccount 密钥对 | `sa.key` / `sa.pub` | 无证书（RSA 密钥对） |

核心不变量：
1. **SAN 全部来自变量**（inventory 分组 + `k8s_vip` + 服务网段），**禁止硬编码**；
2. **私钥 600 / 证书 644**，目录 700；
3. **重跑不覆盖「仍有效」的既有证书**（内容 sha256 不变，`changed=0`）；
4. 证书/私钥**绝不入库**（`.gitignore` 已覆盖 `*.key`/`*.crt` 等）。

## 2. 非目标（明确不做什么）
- 不生成 `controller-manager` / `scheduler` / `kube-proxy` 客户端证书（控制面清单由 T006/T007 负责；
  本 role 的证书清单是**数据驱动**的 `pki_certs`，后续任务只需追加条目，无需改代码）。
- 不做 kubeconfig 文件渲染（`admin.crt` 已就绪；kubeconfig 生成属 T007/T008）。
- 不把 kubelet 证书**分发**到各节点（本 role 在控制面生成全部节点证书；分发属 T008/T014）。
- 不做证书**吊销（CRL）/ 轮换编排（自动 renew 任务）/ 集群外 CA 注入**。
- 不接入 `playbooks/site.yml`（编排属后续任务）。
- **不实现**：SAN 集合变化时自动重签（改 inventory 增减节点后需显式 `pki_force_regen=true`）；
  已在 §5「声明为不在范围」。

## 5. 幂等与例外
- 幂等期望：同参数连跑两次，第二次 `changed=0`，且**不触碰**任何既有产物（sha256 不变）。
- **有意的 `changed=1` 例外（自愈语义）**：产物「缺失 / 无法解析 / 已过期或进入续期窗口
  （`pki_renew_before_seconds`，默认 30 天）/ 与私钥不匹配 / 其签发 CA 被重建」时**重新生成**。
  理由：宁可自愈，也不要让集群拿着坏证书启动。
- 证书**只有证书文件被重签**时才重新签发；私钥仅在「缺失或不匹配」时重建（避免无谓的密钥轮换）。
- **明确不在范围**：SAN 集合变化（如新增 master）**不会**触发自动重签——需显式 `pki_force_regen=true`
  （或删除旧证书）。理由：避免每次 inventory 变动都全量重签导致集群中断；README 已声明。
- **受限声明（对应 spec R1）**：
  - 本环境 `community.crypto` 不可用（目标解释器无 `cryptography`）→ 改用 `openssl` CLI，已实测记录（§3/§9.0）。
  - 本 role 的**真实用途是集群内证书**，但**禁止**在共享开发机上写真实 `/etc/kubernetes`；
    故全部验证在**沙箱前缀**（`pki_root_prefix`）下真实执行：真生成密钥/真签名/真落盘/真验证链。
    `pki_root_prefix` 是**测试用途**变量，生产保持空串即 `/etc/kubernetes/pki`。
  - **未验证项**：多节点分发（kubelet 证书拷到各节点）、apiserver/kubelet 进程真实加载证书、
    与真实 etcd/kubeadm 的互操作、集群运行时握手。需真机/VM 复验（步骤见 §6）。
  - 证书**到期**用 `openssl x509 -not_after <过去时间>` **真实构造**已过期证书验证，非 mock；
    验证「时间流逝导致的过期」不在本环境范围（无时间旅行），同一代码分支已由已过期证书覆盖。
- 全部测试离线：仅用本地 `openssl` 与 ansible，无网络依赖。

## 7. 风险与假设
- 假设：目标机存在 `openssl`（OpenSSL 1.1.1+/3.x）。role 启动即 `assert` 探测，缺失则 fail fast。
- 假设：`openssl x509 -checkend` 的返回码语义（0=窗口内不会过期）——已实测（§9.0/E1）。
- 风险：`openssl genpkey -out` 写出的私钥默认权限受 umask 影响（实测 644），
  故 role **显式** `file: mode=0600` 兜底（§9.0/E2）。
- 风险：`-CAcreateserial` 的序列号文件放在构建目录（非 pki 目录），避免污染生产目录（已在实现中处理）。

## 10. 实现说明与实验证据

### 10.1 文件与职责

| 文件 | 职责 |
| --- | --- |
| `roles/pki/defaults/main.yml` | 全部可配置项：路径前缀、算法/摘要/有效期、权限、重建策略、拓扑分组名、SAN 附加项、`pki_cas` 与 `pki_certs` 数据清单 |
| `roles/pki/tasks/main.yml` | 入口：check → facts → dirs → ca → cert → kubelet → sa → verify → cleanup（tags `pki:*` 可单跑） |
| `roles/pki/tasks/facts.yml` | **SAN 的唯一来源**：从 `groups[...]` + `k8s_vip` + `k8s_service_cidr` + `ansible_host` 推导；缺拓扑即 assert 失败 |
| `roles/pki/tasks/_needs_regen.yml` | 幂等判定（stat + `openssl x509 -checkend` + 证书/私钥公钥比对 + `pki_force_regen`） |

| `roles/pki/README.md` | 变量、产物、幂等语义、范围说明 |

### 10.3 SAN 来源变量（无硬编码）

| 证书 | SAN 组成（去重后） |
| --- | --- |

### 10.4 `pki_dir` 可重定向（沙箱真实执行）

`pki_dir = {{ pki_root_prefix }}{{ pki_config_dir }}/pki`，`etcd/`、`kubelet/`、`sa.*`、构建目录
（`pki_root_prefix/var/cache/kubernetes-pki`，默认用后清理）全部由它派生。
生产：`pki_root_prefix=""`、`pki_config_dir=/etc/kubernetes` → `/etc/kubernetes/pki`。
测试：`-e pki_root_prefix=<mktemp -d>`，配合 `pki_file_owner/group={{ omit }}` 以普通用户运行；
因此生成过程（真密钥、真签名、真落盘、真验链）与生产同一代码路径，宿主 `/etc/kubernetes` 零接触。

### 10.5 openssl 幂等判定方式

对每个「证书 + 私钥」对（`_needs_regen.yml`）：

1. `stat` 两者 → 是否存在；
2. `openssl x509 -in <cert> -noout -checkend <pki_renew_before_seconds>`：`rc=0` 表示「在未来窗口内不会过期」；
3. `openssl x509 -noout -pubkey` 与 `openssl pkey -pubout` 输出逐字节比较 → 证书-私钥是否匹配（实验 E3）；
4. `pki_needs_key = force | 私钥缺失 | (证书与私钥均可读且公钥不一致)`；
   `pki_needs_cert = needs_key | force | 证书缺失 | checkend≠0`；
5. CA 额外用**重建前后证书 sha256 对比**得出 `pki_ca_rebuilt[<ca>]`，leaf 的
   `pki_cert_needs_issue = needs_cert | pki_ca_rebuilt[ca]`。

只有判定为「需要」的任务才会执行（`when:`），其余任务 skip → 有效证书零触碰、`changed=0`。
落盘原子性：先写入构建目录（CSR/`*.crt`/扩展/CA 序列号），成功后再 `copy` 到最终路径，
签名失败不会破坏既有证书。私钥权限由 `file: mode=0600` 显式兜底（`genpkey` 默认受 umask，实测 644，实验 E2）。

### 10.6 `pki_force_regen` 语义

- 默认 `false`：不打扰既有有效证书；
- 置 `true`：**本次运行**对所有 CA / leaf / SA 密钥对强制重建（密钥与证书一并轮换），用于
  SAN 集合变化（新增 master/node）等「需要显式重签」的场景；
- 重建后 `changed>=1`，且全部链式校验仍然自洽（测试 A15b 断言）；
- 不是常驻开关：设一次即可，后续运行恢复 `false` 后回到「不覆盖有效证书」的正常语义。

### 10.7 实验证据（补充 E0–E3 的落地位置）

| 实验 | 落地 |
| --- | --- |
| E0（`cryptography` 缺失 → 不用 `community.crypto`） | 全 role 仅用 `ansible.builtin.command` 调 `openssl`；无 collection 依赖（`meta/main.yml` dependencies 为空） |
| E1（`-checkend` 返回码语义） | `_needs_regen.yml` 的 `pki_needs_cert`；测试 A13b 用 `-not_before/-not_after` 构造**真实已过期**证书验证 |
