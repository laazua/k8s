## 1. 目标（本任务交付什么）

1. `tests/add-node` 的**零影响快照**（既有节点/控制面）逐键校验载荷：空值、`__ERROR__`、`__EMPTY__`、
   必需键缺失一律**显式 FAIL 并打印键名**，不允许 `空==空` 静默通过；并带**负例测试**（注入空值/哨兵 → 断言被判无效）。
2. **证书幂等真实化**：`sign` 模式首跑把 CA/证书/私钥的**内容哈希**记录在节点上；重跑以「记录哈希
   + 链验证 + CN/O + `-checkend`」判定 unchanged。节点 CA 被替换 → **显式失败（rc≠0，不重建 CA）**；
   kubelet leaf 证书被篡改/失效 → **自愈（用既有 CA 重签，changed>0）**；复跑回到 changed=0。
3. 关闭 T014-r1 的 D3–D8（见 §9 逐条结论），并保持 `make test-add-node` 计数只增不减、两次连跑逐条一致。
4. **不改变** T014 验收摘要与已 accepted 的共享 role 语义（`roles/pki|node|control-plane` 不动）。

## 2. 非目标（明确不做什么）

- 不重写 add-node 的 CLI/变量契约；不删除任何既有断言（只替换空转/恒真断言为有载荷断言）。
- 不改 `roles/pki`、`roles/kubelet`、`roles/containerd`、`roles/base`；不改 T014 契约与 `spec.md`/`roadmap.md` 验收摘要。
- 不做实现级 mutation campaign；牙齿以 targeted 负例 + 红→绿计数为证。

## 3. 方案取舍

1. **快照守卫**：新增 `snapshot_invalid_keys` / `snapshot_missing_keys` / `snapshot_guard`。
   逐键判定：空值、`__ERROR__`、`__EMPTY__` 恒无效；`__MISSING__` 仅对白名单路径键合法
   （宿主 `/etc/kubernetes`、containerd 目录、`/opt/cni/bin` 在开发机可不存在）；`ports` 允许为空
   （合法基线=无占用）。必需键缺失单独判定 → 打印 `键(缺失)`。
   宿主快照采集（`snapshot_host_state`）内部复用守卫，重试 3 次仍无效 → `bad` + 打印无效键并 rc=1。
2. **证书状态记录**：新增 `add_node_cert_state_file`（默认
   `{{ add_node_pki_dir }}/kubelet/<node>.state`，一行三个 sha256：`<ca> <cert> <key>`）。
   - 首跑签发后写入；重跑 `already_joined` = 凭证存在 ∧ 链验证/CN/O/有效期通过 ∧ 记录哈希与当前一致 ∧ CA 未变。
   - CA 哈希与记录不一致 → `assert` 失败（**显式失败**：add-node 不重建/不替换 CA，无法自愈 CA；
     真机动作=从控制面重新分发正确 CA）。
   - leaf 证书/私钥哈希不一致或失效 → `pki_force_regen: true`（仅此时）→ 用既有 CA 重签（**自愈**）。
   - 从 T014 升级上来的节点（有证书、无记录）：凭证有效则**回填记录**（一次 changed=1，不重签），
     之后按记录哈希判定；凭证无效则重签。
3. **为什么用记录文件而不是「仅 pki `_needs_regen`」**：pki 的判定只看「有效且匹配」，无法发现
   「被替换为同 CA 签发的另一张有效证书」；记录哈希补上内容级比对，且 CA 替换可判定。
4. **D4 `--check`**：cert.yml 的签发/状态写入/构建目录清理一律 `when: not ansible_check_mode`，
   读路径（哈希、状态记录、CA/证书判定）保留 `check_mode: false`；verify 本就只读。
   测试新增两次 `--check`：①未收敛新 prefix（validate+cert 读路径）②已收敛节点（verify 读路径）。

## 5. 幂等与例外

- 幂等期望：同一 add-node 命令连跑第二次 `changed=0`（`--check` 在已收敛节点同样 changed=0）。
- 声明例外：从「有证书、无状态记录」的既有节点首次运行会写一次记录文件（changed=1），之后 changed=0。
- 自愈路径的 changed>0 是**预期**（重新签发）；随后的复跑必须回到 changed=0。

### 9.2 能力边界与风险

1. **CA 被替换选择「显式失败」而非自愈**：add-node 不持有可信 CA 副本，无法判断哪个 CA 正确；
   自动替换会掩盖篡改。真机动作：从控制面重新分发 `ca.crt`/`ca.key`。已在 README/契约写明。
2. **leaf 自愈会轮换 node2 私钥**：沙箱不重启 kubelet，自愈后不验证注册状态；真机由 kubelet
   重读或 systemd 重启 handler 生效（与 T014 受限项一致，未新增未验证声明）。
3. **从 T014 升级的既有节点**首次运行会写一次 `.state`（changed=1），之后 changed=0；已在 §5 声明。
4. 状态记录不是安全边界：能改证书的攻击者也能改记录；它用于**检测误操作/漂移**，不是防篡改机制。
5. 快照守卫的 `__MISSING__` 白名单按「宿主可不存在的路径」设定；新增路径键必须登记白名单，
   否则会出现显式 FAIL（安全侧偏差，不静默）。
6. 未跑全量 `make test`（成本）；未做实现级 mutation campaign，牙齿以 targeted 负例 + 红→绿为证。
