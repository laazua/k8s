## 1. 目标（本任务交付什么）

三个可独立执行的 Ansible role，用**官方二进制 + systemd**（非 kubeadm、非容器）拉起控制平面：

- `roles/kube-apiserver`：安装 `kube-apiserver`；渲染 **安全默认** 的 systemd unit 与启动参数；
  渲染 `admin.conf` / `controller-manager.conf` / `scheduler.conf`（TLS 客户端证书内嵌），
  并签发控制器/调度器/kubelet-client 三张控制面客户端证书（kubernetes-ca 签发）。
- `roles/kube-controller-manager`：安装并渲染 `kube-controller-manager`（`--kubeconfig`、
  `--authentication-kubeconfig`、`--authorization-kubeconfig`、SA/CA 签名参数、leader election）。
- `roles/kube-scheduler`：安装并渲染 `kube-scheduler`（同上 + 安全端口）。
- 全部版本/架构/URL/sha256/端口/地址/路径/flag **变量化且有默认**；生产不写死。

## 2. 非目标（明确不做什么）

- 不接入 `playbooks/site.yml`；不改 `playbooks/control-plane.yml` 的编排（属 T012）。
- 不改已 PASS 的 `roles/{base,download,pki,etcd,haproxy,keepalived}` 与对应 `tests/`。
- 不实现 kubelet/containerd/kube-proxy/CNI/CoreDNS/RBAC 附加对象（T008–T011）。
- 不实现证书轮换编排、etcd 部署、VIP/LB（T004/T005/T006 已交付）。
- 不在共享开发机写 `/etc/systemd/system`、不 `systemctl enable/start`、不占默认
  6443/10257/10259、不写宿主 `/etc/kubernetes`、不写 `/var/lib/kubelet`。

### 3.3 设计取舍（需 Evaluator 注意）
1. **控制面引导集中在 `kube-apiserver` role**：`roles/pki/README.md` 明确把
   「kubeconfig 渲染、控制面组件客户端证书」划给 T007。为避免 cm/scheduler 两处重复
   openssl 签名逻辑，`kube-apiserver` role 统一签发
   `kube-controller-manager`（O=system:kube-controller-manager）、
   `kube-scheduler`（O=system:kube-scheduler）、
   `apiserver-kubelet-client`（O=system:masters）三张客户端证书，并渲染三份 kubeconfig。
   cm/scheduler role 只**消费并校验**（缺失即 fail-fast）。
2. **kubeconfig 的 server 默认走 VIP**（`k8s_vip:k8s_apiserver_port`），符合 HA 前置 LB；
   单机/测试可覆盖 `kube_apiserver_kubeconfig_server`。
3. **组件身份分离**：不使用 admin 证书跑 cm/scheduler；内置 ClusterRole
   `system:kube-controller-manager` / `system:kube-scheduler` 直接生效（leader election 可用）。
4. **kubelet client 证书**：由本 role 签发 `apiserver-kubelet-client`，供 apiserver 访问 kubelet
   （`--kubelet-client-certificate/key`）；kubelet 侧签发/分发属 T008。
5. **systemd 进程用户默认 root**：kube-apiserver 需读 0600 私钥；cm/scheduler 也用同一属主模型。
   `kube_*_user` 可覆盖（非 root 时需自行分发 0600 凭据，属后续任务）。

## 5. 受限声明（对应 spec R1 / C13）

### 5.1 systemd active/enabled **未在宿主真实执行**（受限）
- 共享开发机禁止 `systemctl enable/start`、不写 `/etc/systemd/system`。因此「三组件 systemd
  active+enabled」在测试中以**静态/半动态**方式验收：
  1. role 的 `service.yml` 使用 `ansible.builtin.systemd` 且 `enabled/service_state` 可配置，
     默认 `true/started`；handler `daemon_reload` + `restart`；
  2. unit 渲染到沙箱并断言 `[Install] WantedBy=multi-user.target`、`Restart=always`、
     `LimitNOFILE`、`After=network-online.target`、`ExecStart` 全部关键 flag；
  3. **用 unit 的 ExecStart 真实拉起三进程**，证明 unit 可直接执行（排除「只渲染不能跑」）。
- **真机复验（必做；已从占位 playbook 换成可执行 playbook）**：
  `playbooks/control-plane.yml` 仍是骨架占位（编排属 T012），**不要**用它做复验。
  使用本任务自带的真机 playbook（真实路径 + `manage_service=true`，会写 `/etc/systemd/system` 并
  `enable/start`，**只允许在目标真机执行**）：
  ```bash
  # 0) 前置：PKI（T004）、etcd（T005）已就绪；inventory 含 [k8s_master]/[etcd] 与 k8s_vip。
  #    本地 inventory 被 .gitignore 忽略（不会入库），从样例复制后填真实主机：
  cp -n inventory/hosts.example inventory/hosts.ini
  $EDITOR inventory/hosts.ini        # 填 ansible_host / k8s_vip / etcd 地址等
  ansible-playbook -i inventory/hosts.ini --syntax-check tests/control-plane/real_services.yml  # 期望 exit 0
  ansible-playbook -i inventory/hosts.ini tests/control-plane/real_services.yml
  #    期望：三个 role 真实执行（播放 recap 含 changed>0），无 debug 占位、无 fatal

  # 1) systemd 生效
  systemctl is-enabled kube-apiserver kube-controller-manager kube-scheduler   # 期望三行 enabled
  systemctl is-active  kube-apiserver kube-controller-manager kube-scheduler   # 期望三行 active
  systemctl show -p ExecStart kube-apiserver | tr ';' '\n' | grep -- '--anonymous-auth=false'

  # 2) 集群可用性（真机 admin.conf 由 role 渲染在 /etc/kubernetes/）
  kubectl --kubeconfig /etc/kubernetes/admin.conf get --raw /healthz            # ok
  kubectl --kubeconfig /etc/kubernetes/admin.conf get --raw /readyz             # ok
  kubectl --kubeconfig /etc/kubernetes/admin.conf get ns                        # 含 default/kube-system

  # 3) 匿名访问（严格 401）
  curl -k -s -o /dev/null -w '%{http_code}\n' https://<VIP>:6443/api            # 401
  curl -k -s -o /dev/null -w '%{http_code}\n' https://<VIP>:6443/api/v1/namespaces  # 401

  # 4) 幂等：同命令再跑一次，期望 changed=0（服务不被重启：PID 不变）
  ansible-playbook -i inventory/hosts.ini tests/control-plane/real_services.yml
  ```
  期望：三 unit `enabled`+`active`；healthz/readyz `ok`；匿名访问 **401**；第二次 `changed=0`。
  回滚：`systemctl disable --now kube-apiserver kube-controller-manager kube-scheduler`
  （不删 `/etc/kubernetes` 与 etcd 数据，便于排查）。

## 7. 风险与假设

- 假设 `k8s_master` 有可用的 `ansible_host`；否则 `--advertise-address` 需显式覆盖。
- 假设 PKI 产物存在且与 CA 匹配；role 在写入任何 unit 前 fail-fast。
- 假设 etcd 已就绪（T005）；role 仅校验 endpoint 配置非空，不代替 etcd 健康检查。
- 风险：官方 `.sha256` 侧车是「传输层可信」而非固定哈希；生产建议显式固定
  `kube_*_sha256`（离线部署必须固定，role 对「制品已存在但未固定哈希」直接失败）。
- 风险：cm/scheduler 的 leader election 需要 apiserver 的 RBAC 内置角色；测试已验证
  `system:kube-controller-manager`/`system:kube-scheduler` 可用；自定义授权模式需另行验证。
