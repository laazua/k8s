## 1. 目标（本任务交付什么）

交付 `tests/e2e/smoke.sh`：**一条命令**完成集群冒烟，输出逐项 `PASS/FAIL/SKIP` 与
`RESULT`/`PASS`/`FAIL`/`SKIP` 汇总，退出码可被 CI 判定。

两种模式：

- `--static-only`：交付物完整性 + 全部 playbook `--syntax-check`（秒级）。
- `--mode sandbox`（默认）：真实拉起 pki → 单成员 TLS etcd → kube-apiserver →
  containerd → kubelet → cluster-addons（kubeconfig/RBAC）→ CoreDNS 官方二进制，
  断言控制面健康、节点注册与 Ready 条件、kubeconfig 身份、RBAC 边界、集群域 DNS。
- `--mode real --kubeconfig PATH [--image IMG]`：真机验收（节点全 Ready、
  kube-system Pod 全 Running、kube-dns 存在；有镜像时追加集群内 DNS Job）。

同时交付 `tests/e2e/test_smoke_contract.sh`（脚本自身的契约验收）与 `README.md`。

### 1.1 方案选择（必须声明）

**选择：沙箱模式只断言「无镜像也真实可测」的集群不变量；镜像依赖项显式 SKIP。**

理由：

1. 目标验收的 4 项中，「系统 Pod 全部 Running」「集群内 DNS」「跨节点 Pod 互通」
   依赖镜像/CNI 运行态；本环境 registry 不可达、无镜像（spec R1 v1.4），伪造不可接受。
2. 其余不变量可以**真实**验证：节点确实由真实 kubelet 注册、apiserver 确实以 TLS
   提供服务、CoreDNS 官方二进制确实按 role 渲染的 Corefile 解析出真实 Service IP。
3. `SKIP` 与 `FAIL` 分离：CI 可区分「环境受限」与「回归失败」；真机执行 `--mode real`
   后 SKIP 会转为实检。
4. 沙箱编排复用已评估的 T007/T008/T011 资产（sandbox stack、unit ExecStart、
   cluster-addons role），不引入新实现路径。

## 2. 非目标（明确不做什么）

- 不拉镜像、不创建 Pod（sandbox 模式）；不实现 CNI 数据面（T010 已交付）。
- 不实现节点加入/升级流程（T014/T015）。
- 不修改任何 role、已 PASS 的测试套件或 `Makefile` 既有目标（仅新增两个目标）。
- 不在宿主写 `/etc/kubernetes`、`/etc/systemd/system`，不 `systemctl start/stop` 业务服务
  （只清理 `kubepods.slice`）。
- 不在 real 模式自动投放跨节点 Pod（拓扑相关，需人工指定）。

## 3. 依赖、环境事实与设计取舍

### 3.1 依赖

T007（控制面）、T008（containerd/kubelet）、T011（kubeconfig/RBAC/CoreDNS）已 accepted。

### 3.2 环境事实（2026-11-12 实测）

| 探测 | 结果 | 结论 |
| --- | --- | --- |
| docker registry / 镜像 | 不可达 / 无镜像 | Pod/DNS/跨节点只能 SKIP |
| `sudo -n` | 可用 | 沙箱进程 root 拉起、0700 PKI 目录断言 |
| 制品缓存 | kubectl/apiserver/kubelet/containerd/runc/CNI/crictl/etcd/coredns 全命中 | 离线可复跑 |
| 真实 kubelet | 可注册 `node1`，`Ready=False/KubeletNotReady`（无 CNI） | 断言 Ready 条件 + reason |
| CoreDNS 1.11.3 | 可运行并解析 kubernetes.default | 真实 DNS 检查成立 |

### 3.3 设计取舍（需 Evaluator 注意）

1. **不 `unshare -n`**：与 T008 一致，直接使用高位端口（16443/12379/20250/20248/15353），
   避免 netns 内 containerd/kubelet 额外变量；沙箱路径 + PID 精确停止保证不污染宿主。
2. **`Ready=False` 视为通过**（条件是「存在且可诊断」）：无 CNI 时 kubelet 必然 NotReady；
   sandbox 断言 `Ready ∈ {True,False}` 且 NotReady 有 reason。
3. **RBAC 反例用 `create serviceaccounts`**：沙箱 apiserver 为 `RBAC,Node`，
   Node authorizer 会放行 secrets/pods（`create serviceaccounts` 仍被拒绝）。
   纯 RBAC 边界由 T011 的 RBAC-only 沙箱覆盖。
4. **CoreDNS 取 admin 证书作 TLS 客户端**（含 clientAuth），与 T011 一致。
5. **`SKIP` 必须显式**：脚本固定输出 3 条 SKIP，meta-test 断言 `SKIP>=3`，防止把受限项静默吞掉。
6. **异常清理不依赖 `wait`**：按沙箱二进制路径 `pkill -TERM` → 超时 `-9`，
   再 `rm -rf` 沙箱；kubelet 的 `kernel.panic*` 与 `kubepods.slice` 恢复/清理。

## 5. 受限声明（对应 spec R1 v1.4 / C13）

1. **系统 Pod Running 未验证**：无镜像，`kube-system` 中不存在可调度 Pod；
   sandbox 固定输出 SKIP。
2. **集群内 DNS（kube-dns ClusterIP:53）未验证**：CoreDNS 以宿主进程 + 高位端口运行，
   不等于集群内解析；真机 `--image` 时用 Job 验证。
3. **跨节点 Pod 互通未验证**：需真实 CNI + 镜像 + 多节点；real 模式仅提示 SKIP。
4. **CNI 未装导致 Node NotReady**：sandbox 只断言 Ready 条件存在且有 reason，
   不声称节点可用。
5. **真机步骤**：

```bash
tests/e2e/smoke.sh --static-only
tests/e2e/smoke.sh --mode real --kubeconfig /etc/kubernetes/admin.conf \
  --image <集群可达镜像>
# 期望：RESULT=PASS；SKIP 为空或仅剩「跨节点 Pod」（需人工投放）
```
